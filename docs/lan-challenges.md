# 联机挑战

## 行为与原版复用

大厅由房主选择挑战，编号从 1001 开始；切换规则会清空所有人的准备状态。当前 **1001 盲袋接力** 固定普通难度、里该隐开局，2–4 人按固定栏位形成观察环：P1 → P2 → … → P1。实际材料、旋转和合成仍属于操作者，只显示下一位的材料与原生预览。死亡、掉线和重连不重排观察环；下一位无法显示时不切换到其他人的袋子。变身与其他道具仍走普通联机规则。

终点为羔羊：在 Dark Room 的羔羊房清场后，把原版结局宝箱变为原版奖杯。任意在线、存活且非幽灵的队员领取后，房主发布一次可靠结束事件；各端调用原版 `Game::FinishChallenge` 的淡出／返回菜单流程，不记录原版挑战解锁。低解锁存档的提前结局宝箱继续向目标楼层推进，最后两层走 Sheol → Dark Room；其他终局被拦截后，在安全更新点返回 Dark Room。胜利绕圈不适用于本挑战。

左侧属性栏上方的终点使用原版 HUD 的 `Destination` 绘制分支，沿用原版精灵、位置计算、角色额外计数行与 HUD 偏移。百宝袋也沿用原版绘制，仅过滤允许显示的角色。已适配 EID 的本地配方面板在此规则下隐藏，普通道具说明保留；不修改第三方 Mod 源码或配置。

挑战暂不持久保存或续玩，退出也不覆盖／删除已有普通联机存档。客机可通过现有内存检查点重连；规则 ID／版本、原栏位与材料随检查点和实时视图恢复。R 键和沙漏不清除会话规则。

未来地图由 `maps[id]` 注入两个可选回调，1001 不配置地图模块：

- `onLayoutReady(info, level)`：房主的新层／重建已可用时调用，可衔接布局构建；不在原生加载回调里递归换层。
- `canEnter(ctx)`：房主在房间迁移入队前判断，包含 `slot`、源／目标房间与维度、`teleport`、`info`；存在策略时只接受明确的 `true`。普通门和经过队列的传送共用检查。

这里只预留调用边界，没有提供绘图格式、房间构建器或通用地图同步扩展。以后加入手绘地图时，应同时实现布局采集／应用、恢复和全队强制汇合的拒绝策略；不能仅靠这个回调完成所有地图能力。

## J460 原生边界

现有材料读写接口不能分别控制材料与预览的显示，Lua HUD API 也不能为独立联机规则指定原版终点。新增以下受版本特征校验的能力：

| 入口／布局 | 用途与约束 |
| --- | --- |
| `PlayerHUD` 百宝袋绘制，RVA `0x449510` | `ECX=PlayerHUD*`、栈上 `Vector*`、`XMM2=scale`，被调方清理 4 字节；完整保留寄存器与 SSE。该函数同时画材料和缓存预览 |
| `PlayerHUD[0]`、Player `+0x1618`／`+0x20a9` | 只读借用角色、控制器和幽灵标记；不替换 HUD 绑定、不写材料、不拥有角色或精灵 |
| HUD 终点存在标记，RVA `0x5a4eae` | 只更改原版绘制栈帧中的两个显示标记，复用后续完整布局／绘制 |
| `Game::GetChallengeParams`，RVA `0x306940` | 仅对 HUD 的指定调用点返回标量目标视图；其余调用保持原版返回值。目标视图无原生容器所有权，不进入玩法或析构 |
| `Game::FinishChallenge`，RVA `0x304f20` | 在全队接受结束事件后的安全更新边界调用；原版 `Game::Challenge` 保持 0，避免套用原版挑战规则或解锁编号 |

所有入口与调用点列在 `entrypoints.h`／`signatures.inc`。协议提升为 **27**，检查点封装为 **save/3**；WorldState schema 保持 **15**，扩展指纹仍须相同。材料完整同步，因此显示限制不是防作弊或数据保密机制。

## 验证边界

离线回归入口为 `tests/challenges.lua`、`challenge_menu.lua`、`challenge_eid.lua`，以及 C++ `challenge-rules`、网络 `run-rules` 和两个 Windows x86 HUD ABI 测试。它们覆盖权威奖励、重复触碰、错误房间、重连／回退后的判定、规则切换竞态、2–4 人栏位与绘制调用约定；不能替代游戏画面与原生流程验收。

本次不启动游戏。后续集中验收：2／3／4 人同房和分房的袋子与预览；EID；不同 HUD 偏移下的终点位置；羔羊清场、任意队员领取和全队返回；低解锁及其他终局路线；死亡／复活、掉线重连、R 键、沙漏；挑战退出后的普通联机、单机 Continue 与原有联机存档。
