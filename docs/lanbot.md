# LAN 人机托管

通过游戏原生控制台把本机 LAN 玩家交给人机，主要用于“人机主机＋人工客机”的同步测试。模块内置在 LAN 扩展中，无需额外 Mod、外部 Agent 或 API Key。

## 启用

启动游戏前，在 Repentance+ 的 `options.ini` 中设置 `EnableDebugConsole=1`。Windows 通常位于 `%USERPROFILE%\Documents\My Games\Binding of Isaac Repentance+\options.ini`，使用自定义存档目录时以实际目录为准。扩展不自动改动配置。

正常开始 LAN 游戏后，按原生控制台快捷键（通常为 `~`／反引号键，取决于键盘布局），输入：

```text
lanbot on
```

关闭控制台后开始托管，默认目标为 `run`，风格为 `balanced`。主机与客机均可使用；每条命令只影响输入命令的机器所属玩家。双角色共享原有本机输入，观察与寻路以首个存活的本机角色为参考。

同机双实例测试需要主机在失焦后继续运行，可在启动前设置 `PauseOnFocusLost=0`。

## 命令

| 命令 | 作用 |
| --- | --- |
| `lanbot on` | 开启或继续托管；重复开启不创建额外控制器 |
| `lanbot mode run` | 收集免费资源、完成当前层正常可达分支，再寻找出口并推进普通路线 |
| `lanbot mode explore` | 探索当前层可达分支，完成后等待，不自动换层 |
| `lanbot mode hold` | 战斗和恢复后留在当前房间，不主动过门 |
| `lanbot style aggressive` | 较近的输出距离，偏重击杀高威胁目标 |
| `lanbot style balanced` | 均衡考虑危险、距离和前进效率 |
| `lanbot style cautious` | 增加危险裕量和权重，偏好更远的有效输出位置 |
| `lanbot pause` | 释放人机按键，恢复人工操作；保留模式和风格 |
| `lanbot resume` | 恢复暂停中的托管，重新读取当前状态 |
| `lanbot off` | 清除任务并恢复人工操作；保留本次会话的模式和风格 |
| `lanbot next` | 在 `run`／`explore` 中沿正常路线前往已知出口，跳过本次队友等待 |
| `lanbot status` | 查看状态、主客机身份、模式、风格、任务、等待原因及决策统计 |
| `lanbot help` 或 `lanbot` | 查看命令帮助 |

可以在开启前设置模式和风格；配置命令本身不启动托管。`on` 和 `resume` 要求 LAN 会话已经开局。关闭状态下的 `resume` 提示先执行 `on`。未知或多余参数只输出错误。

`run` 先完成当前层正常可达分支，不因发现出口而立即结束探索；冷却中的失败路线不会被当作探索完成。随后在普通出口等待其他在线且存活的队友进入出口房间，显示 `wait_for_party`。`next` 只改变人机这一次的等待和选路，仍通过正常移动触碰出口；它不生成出口，也不绕过游戏或 LAN 的限制。`hold` 拒绝 `next`。

`pause` 只暂停人机。暂停或关闭托管不会撤销已经发生的移动、拾取、伤害与进度，也不能撤回已经发送到对端的输入。退出、断线或新一局关闭托管并恢复默认配置，重连后需要重新开启。

## 行为与边界

人机接管移动和射击，真人仍可操作地图、暂停、控制台、炸弹、主动道具和卡牌。打开界面、换房、世界重建、本机死亡或视图未就绪时清理旧玩法输入；客机已观察的权威 tick 超过 250 ms 未变化时等待 `stale_view`，新状态到达后恢复。决策异常时转为暂停，记录错误。

本地观察读取当前本机角色和房间。探索图从实际观察的门逐步建立；局部路径使用有展开上限的 A*，实时走位评估九个移动方向的短时轨迹，考虑惯性、网格、敌人、移动弹幕、激光线段及即将爆炸的炸弹。弹幕使用连续相对轨迹判断，客机观察年龄用于位置外推；到达路径点后继续预测减速与危险。战斗站位考虑危险、视线、射程和周边退路，并保持短期目标稳定，跳过标记为不可选中的敌人。普通射击按射程和视线判断；硫磺火、刀、科技 X 和巧克力牛奶使用充能与松开策略，松开跨越至少三次渲染采样，避免被 30 Hz 网络采集跳过。按渲染帧去重，网络发送和客机预测复用同一份合成输入，超过三帧未更新的输入归零。

路线被可射击的大便挡住时，先通过正常射击破坏挡路网格；破坏前不把障碍当作可行走格子，岩石和炸药桶仍不自动处理。清房后拾取可接收的免费心、金币、钥匙、炸弹与道具，每间 Boss 房间自动领取至多一份道具奖励。已有主动道具时保留当前道具并绕开地上主动道具，避免反复交换。进房后先走离门口，再选择战斗或探索目标；回溯只用于前往剩余分支或出口。出口按触碰范围保护，只有当前选中的出口任务可以接近，不开放其他出口；保护覆盖未清房的楼梯和地板出口。已知受阻目标按来源房间进入冷却，再尝试其他路线。全部分支完成、资源不足或出口受阻时等待，分别显示 `exploration_complete`、`resource_missing`、`route_blocked` 等原因。

支持普通模式，以及贪婪模式的普通波次、Boss 波次和原生换层。贪婪模式在启动按钮前等待存活队友进入同一房间，战斗期间避开停止按钮，Boss 波次完成后补给、收集可达道具房，再寻找贪婪出口；跳过可选恶魔奖励波。贪婪商店在缺钥匙或缺血且金币足够时购买钥匙或恢复用心；买到资源后不重复追逐相同需求。商店被动／跟班道具按品质、伤害／射速、生命收益和重复持有情况估计价值，在预留钥匙与补血费用后购买；未知或负代价商品、主动道具不自动购买。挑战等待人工处理；不自动使用炸弹或主动道具、在普通模式购物、进入诅咒／献祭／挑战／隐藏房，也不处理特殊结局解谜。普通压力按钮（variant 0）在清房前也会被逐个处理，以按钮 State=3 确认激活，未激活时显示 `button_not_activated`；贪婪按钮只在原生动画表明可启动且房间已清空时接近；奖励、轨道和其他特殊按钮仍需人工处理。非飞行角色避开尖刺与已识别的敌方红／绿／黄／白／黑地面效果。交替尖刺先观察完整收起周期，靠近安全等候点，预留通过与转向时间后再穿越；清房后已收起且没有倒计时的尖刺可以直接通过，安全窗口不足时显示 `wait_for_trap`；观察中断、换房或角色替换会重置周期，持续无法确认窗口时显示 `needs_manual`。蓄力时长、移动速度与危险轨迹采用近似值，复杂武器组合、双角色独立走位、特殊地形和未识别的 Boss 预兆仍需实机验证。`run` 表达推进目标，不保证每个种子和角色都能自动通关。

`status` 中 `frames` 为完成决策的次数，`hits` 为相邻有效观察之间的血量下降次数，`blocked` 为受阻决策次数，`max_ms` 为观察与决策的最高耗时。`combat` 显示寻找输出位置或绕行阶段，`move` 和 `candidates` 显示本帧移动方向与评估数量。2 ms 是设计目标，不是已经验证的实时保证。

贪婪模式另有每层持久的 `fight`、`supply`、`loot`、`gather`、`leave` 阶段；`status` 显示 `phase`、`phase_reason` 和 `goal`。补给完成后先访问钥匙预算可达、尚未访问的道具房，再向出口集合，本层不再反复进入商店补给；跨层重新开始。大型房间的不同入口归并为同一个探索节点。前进直线上处于射程内的大便立即转为正常射击清障，普通／红火堆也会射击熄灭；蓝火、紫火避让并保留给人工处理。

贪婪道具优先分配给装备较少、预计收益较高的存活队友，购买还会检查接收者的预算。其他 BOT 会绕开预留道具；持续不可达的预留会过期。清房后的安全斜向路线用于绕开密集商品，并处理补货后站在避让圈内的情况。

## 普通路线优化验证（历史）

完整离线检查通过：50 项 CTest、104 项 pytest 和 19 项子测试；其中 LANBOT 为 52 项 Lua 检查与 46 项持续行为场景。覆盖四向岔路、门边惯性、先探索再换层、多个出口独立保护、普通按钮、交替尖刺、连续弹幕，以及闭合出口、大宝箱退让和客机预测位置差异。Windows x86 Release 构建及 75 项检查通过。隔离双实例在同一对进程中通过七项行为检查，再由主客机各自 LANBOT 完成第一层至 Lamb 结局，双方正常退出、存档恢复通过。完整流程使用用户允许的保护、生成 Boss 房定位与有限伤害加速，战斗、移动、出口碰撞、换层与结局由真实 BOT 输入和原版触发；单向延迟 75 ms。实机证据、失败履历与性能记录见[验收记录](lanbot-verification.md)。

补充[九蜘蛛纯走位演示](lanbot-spider-demo.md)：客机以撒三颗红心，初始房间中央 3×3 九只普通蜘蛛；先静止，启动 LANBOT 后释放。夹具屏蔽射击，不改变现有走位策略，本轮存活 15.531 秒，六次受击死亡，九只蜘蛛全部存活且没有泪弹。记录包含重现方法、逐次扣血时间和录像位置。

后续近身敌群优化加入持续绕行、停顿敌人的追击压力与输入延迟预测；设计和回归见[走位优化记录](lanbot-dodge-optimization.md)。普通托管继续射击，纯走位演示单独过滤射击输入。

## 初版验证记录

新增无需游戏的 Lua 测试覆盖控制台回调、命令与生命周期、本机归属、模式与风格、岔路探索、出口等待、路径受阻、障碍绕行、动态危险和蓄力射击。原生输入测试覆盖人工／人机切换、界面输入保留、按下边沿、预测一致性与过期释放，并纳入现有 CTest／CI。

[离线行为场景](offline-testing.md)持续运行真实人机代码，覆盖四向过门、速度／碰撞半径／起点组合、绕墙、留守与暂停恢复；三个门前／路径点停滞场景作为固定回归保留。模拟运动模型不能单独证明原生物理、真实战斗或实际通关通过。

隔离双实例使用 Repentance+ 1.9.7.17.J460、种子 `LBCD0G4M` 和双阿撒泻勒，已验证原生控制台命令、主机接管、`hold` 留房、客机独立过门，以及 `pause`／`resume`／`off` 的人工输入切换。修复了该版本忽略 `lanbot` 命令的问题。

探索实测发现门前停滞；轨迹评分与门边界修复当时只通过持续过门回归测试，后续补充的过门检查见上方验收记录。主客机托管的普通 Boss 房战斗、逐层推进和正常结局已通过上述加速流程；这轮未验收无保护随机地图探索、全部 Boss 预兆／武器、四人、高延迟、特殊解谜及通用走位质量。四人指定配装的普通贪婪验收见下文；其余场景仍需按范围验证。后续优先使用无需游戏的行为回归，实机验证按原生接入风险选择少量场景；[设计文档](lanbot-design.md#验收)保留了验证目标。

## 贪婪模式与当前验收边界

普通贪婪模式固定种子 `YV03 9KQF` 已由两个及四个 LANBOT 分别实际通关：每名以撒开局一个圣心和三个衣架，夹具只发放一次开局装备，后续战斗、补血和购买均走原版规则。前六层全部原生第十波、究极贪婪与原生结局通过，两局所有角色均存活。双人最终道具 13／12 件，四人为 9／10／11／10 件；各端正常退出、堆观察与隔离档案恢复通过。

四人进商店的错误门提示另有原生 API 专项：实际触发入口纠正，P4 落在正确门内侧且网格无阻挡。最新离线为 98 项 LANBOT Lua 检查、56 项 Linux CTest、81 项 Windows CTest、116 项 pytest 与 19 项子测试。配装、完整结果、入口专项及各轮失败记录见[贪婪模式挑战](lanbot-greed-challenge.md)。

上述结果限定于指定配装、固定种子的普通贪婪。随机种子、裸装、贪婪困难与四人高延迟未完成相同通关验收。双人贪婪实机记录的决策峰值为主机 26 ms、客机 23 ms，未达到单次 2 ms 设计目标，不能据此判断平均耗时或稳定帧率；九蜘蛛纯走位最后一次计分约 22 秒死亡，也未证明通用走位质量达标，详见[走位优化记录](lanbot-dodge-optimization.md)。
