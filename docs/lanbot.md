# LAN 人机托管

通过游戏原生控制台把本机 LAN 玩家交给人机，主要用于“人机主机＋人工客机”的同步测试。模块内置在 LAN 扩展中，无需额外 Mod、外部 Agent 或 API Key。

## 启用

启动游戏前，在 Repentance+ 的 `options.ini` 中设置 `EnableDebugConsole=1`。Windows 通常位于 `%USERPROFILE%\Documents\My Games\Binding of Isaac Repentance+\options.ini`，使用自定义存档目录时以实际目录为准。扩展不自动改动配置。

正常开始 LAN 游戏后，按原生控制台快捷键（通常为 `~`／反引号键，取决于键盘布局），输入：

```text
lanbot on
```

关闭控制台后开始托管，默认目标为 `run`，风格为 `balanced`。主机与客机均可使用；每条命令只影响输入命令的机器所属玩家。双角色共享原有本机输入，观察与寻路以首个存活的本机角色为参考。

同机双实例测试需要主机在失焦后继续运行，可在启动前设置 `PauseOnFocusLost=0`。

## 命令

| 命令 | 作用 |
| --- | --- |
| `lanbot on` | 开启或继续托管；重复开启不创建额外控制器 |
| `lanbot mode run` | 收集免费资源，探索、战斗、寻找 Boss 与现有出口，尝试推进普通路线 |
| `lanbot mode explore` | 探索当前层可达分支，完成后等待，不自动换层 |
| `lanbot mode hold` | 战斗和恢复后留在当前房间，不主动过门 |
| `lanbot style aggressive` | 较近的输出距离，偏重击杀高威胁目标 |
| `lanbot style balanced` | 均衡考虑危险、距离和前进效率 |
| `lanbot style cautious` | 增加危险裕量和权重，偏好更远的有效输出位置 |
| `lanbot pause` | 释放人机按键，恢复人工操作；保留模式和风格 |
| `lanbot resume` | 恢复暂停中的托管，重新读取当前状态 |
| `lanbot off` | 清除任务并恢复人工操作；保留本次会话的模式和风格 |
| `lanbot next` | 在 `run`／`explore` 中沿正常路线前往已知出口，跳过本次队友等待 |
| `lanbot status` | 查看状态、主客机身份、模式、风格、任务、等待原因及决策统计 |
| `lanbot help` 或 `lanbot` | 查看命令帮助 |

可以在开启前设置模式和风格；配置命令本身不启动托管。`on` 和 `resume` 要求 LAN 会话已经开局。关闭状态下的 `resume` 提示先执行 `on`。未知或多余参数只输出错误。

`run` 在普通出口等待其他在线且存活的队友进入出口房间，显示 `wait_for_party`。`next` 只改变人机这一次的等待和选路，仍通过正常移动触碰出口；它不生成出口，也不绕过游戏或 LAN 的限制。`hold` 拒绝 `next`。

`pause` 只暂停人机。暂停或关闭托管不会撤销已经发生的移动、拾取、伤害与进度，也不能撤回已经发送到对端的输入。退出、断线或新一局关闭托管并恢复默认配置，重连后需要重新开启。

## 行为与边界

人机接管移动和射击，真人仍可操作地图、暂停、控制台、炸弹、主动道具和卡牌。打开界面、换房、世界重建、本机死亡或视图未就绪时清理旧玩法输入；客机已观察的权威 tick 超过 250 ms 未变化时等待 `stale_view`，新状态到达后恢复。决策异常时转为暂停，记录错误。

本地观察读取当前本机角色和房间。探索图从实际观察的门逐步建立；局部路径使用有展开上限的 A*，实时走位评估九个移动方向的短时轨迹，考虑惯性、网格、敌人、移动弹幕、激光线段及即将爆炸的炸弹。普通射击按射程和视线判断；硫磺火、刀、科技 X 和巧克力牛奶使用充能与松开策略，松开跨越至少三次渲染采样，避免被 30 Hz 网络采集跳过。按渲染帧去重，网络发送和客机预测复用同一份合成输入，超过三帧未更新的输入归零。

清房后拾取可接收的免费心、金币、钥匙、炸弹与道具，每间 Boss 房间自动领取至多一份道具奖励。已知受阻目标会进入冷却，再尝试其他路线。全部分支完成、资源不足或出口受阻时等待，分别显示 `exploration_complete`、`resource_missing`、`route_blocked` 等原因。

初版面向普通模式。贪婪模式与挑战等待人工处理；不自动使用炸弹或主动道具、购物、进入诅咒／献祭／挑战／隐藏房，也不处理特殊结局解谜。交替尖刺按不可通行处理。蓄力时长、移动速度与危险轨迹采用近似值，复杂武器组合、双角色独立走位、特殊地形和未识别的 Boss 预兆仍需实机验证。`run` 表达推进目标，不保证每个种子和角色都能自动通关。

`status` 中 `frames` 为完成决策的次数，`hits` 为相邻有效观察之间的血量下降次数，`blocked` 为受阻决策次数，`max_ms` 为观察与决策的最高耗时。2 ms 是设计目标，不是已经验证的实时保证。

## 本次验证范围

新增无需游戏的 Lua 测试覆盖控制台回调、命令与生命周期、本机归属、模式与风格、岔路探索、出口等待、路径受阻、障碍绕行、动态危险和蓄力射击。原生输入测试覆盖人工／人机切换、界面输入保留、按下边沿、预测一致性与过期释放，并纳入现有 CTest／CI。

按本次要求不启动真实游戏。真实控制台、双端同步、连续通关、走位效果和实际帧耗时尚未验收；[设计文档](lanbot-design.md#验收)保留了后续验证场景。
