# 两个 LANBOT 的贪婪模式挑战

目标是回答真实战斗能力问题：普通贪婪模式，两个以撒角色，各自开局获得一个圣心和三个衣架，两个本机控制器都由生产 LANBOT 的 `run` / `balanced` 策略托管。种子为 `YV03 9KQF`，本机双实例延迟设置为 10 ms。初始道具以外的免费资源允许通过原版拾取；贪婪商店允许通过原生拾取购买缺少的钥匙和恢复用心；不自动购买付费道具或使用主动道具。

## 模块与流程

- `lanbot/observe.lua` 在本机房间视图读取模式、楼层、波次、按钮动画和门。挑战模式继续等待 `unsupported_run`。
- `lanbot/terrain.lua` 只把原生 `Off` / `OffSkull`、State=0、清空房间且尚未完成 Boss 波次的贪婪按钮作为目标。普通模式 Boss 波次上限为 10，贪婪困难为 11；第七层不使用该按钮策略。
- `lanbot/greed.lua` 保存每层的“战斗 → 补给 → 集合 → 离场”状态。前六层完成 Boss 波次后进入补给，商店没有可购买的必要资源、离开商店或补给目标持续不可达时进入集合；在出口等齐队伍后离场。已经完成补给的楼层不会重新进入商店补给阶段，新楼层重新开始。`status` 和转换日志带阶段、原因与当前目标。
- `lanbot/planner.lua` 启动贪婪按钮前等待存活队友进入房间。集合与离场阶段只选已知出口及原生贪婪出口门，避免费用需求、未知分支每帧重新竞争。按钮变红时观察模块把它加入避让区域；Boss 波次后也保护可选的恶魔奖励按钮，避免误启动奖励波。
- 观察模块记录未破坏大便及贪婪商店的钥匙／心价格，规划模块只在真实路线被堵时选择需射击的大便。推测路线临时允许大便格，仅用于识别挡路目标；实际移动仍使用原始碰撞图，必须等原版眼泪碰撞打碎后才可通过。已知商店按缺钥匙／缺血和实际价格重新评估，避免因过期资源需求反复进店。
- 付费物品同时作为碰撞避让区域，只有选中的钥匙／恢复用心开放通行，防止寻路途经其他商品时发生原生购买。已有主动道具时避让地上主动道具，防止新旧道具反复交换。
- 观察模块把入口占格索引归并到带维度的 `RoomDescriptor.SafeGridIndex`，门的目的地、已访问节点和队友位置使用相同标识。大型商店从不同入口进入时仍然是同一个房间，避免当作尚未探索的分支；API 差异见 [RoomDescriptor 文档](https://wofsauge.github.io/IsaacDocs/rep/RoomDescriptor.html#safegridindex)。
- 前进直线上处于射程内的大便／可射击火堆在当前决策就进入清障，不等寻路失败或卡住计时。普通与红火堆通过正常泪弹熄灭，蓝火和紫火保留避让区。实际移动必须等原生碰撞／火堆生命值表明障碍已消失，不能直接穿过火焰。
- 寻路、避险与射击沿用原有 LANBOT，通过正常控制器输入触碰按钮、门、地板出口和结局箱。不写波次，不调用按钮 `Reward()`，不改伤害或世界状态。按钮 API 参考 [Lua API 文档](https://wofsauge.github.io/IsaacDocs/rep/GridEntityPressurePlate.html)。

生产改动在 `src/bridge/lanbot.lua` 和 `src/bridge/lanbot/`。联机同步、原生后端和协议不变。贪婪困难的波次边界有离线覆盖，本次实机挑战只验证普通贪婪模式。

## 公平性与结果

`tests/state_lanbot_greed.lua` 仅在第一层、波次 0 时为主客机各增加指定四件道具，并核对数量。血量、伤害、射速和移速由原版道具效果决定。没有免伤、持续回血、自动复活、敌人冻结、清怪、额外赋予道具、瞬移、脚本换层或修改眼泪伤害。实际开局属性和两名角色的血量下降、死亡／原版复活、射击数、波次、楼层均写入日志。

最终 `RESULT` 区分 `win`、`death`、`stalled`、`timeout`。只有第七层的原生 `MC_POST_GAME_END(false)`，以及第一至第七层、前六层 Boss 波次、Ultra Greed 和两名角色的实际射击证据都齐全，才记为通关。队伍死亡或三分钟未推进也能完成一次有效试验；工具的 `passed` 表示夹具正常完成并清理，`lanbot_greed.cleared` 才表示挑战成功。

离线生命周期模型直接执行这份夹具，禁止额外道具、位置／血量写入、免伤、瞬移、伤害和射击代写，并覆盖主客机通关、死亡和卡住的清理路径。单个种子的成败不能代表全部随机种子。

## 执行

先完成离线检查和 Windows Release 构建，然后使用一个隔离主客机进程对。结束后恢复隔离档案，并检查退出码、堆观察结果和新增崩溃转储。

```sh
.deps/checks/bin/python tools/run_special_routes.py \
  --host /mnt/d/isaac-lan-lab/host-001 \
  --client /mnt/d/isaac-lan-lab/client-001 \
  --build build-win32 --output artifacts/lanbot-greed-native-r8-20261011 \
  --case lanbot --case lanbot-greed --latency-ms 10 --port 30990 --heap-check
```

本次结果为未通关：第一层完成战斗、补给和原生换层，最终在第二层第八波停滞。不能以旧的免伤贪婪回归或加速 Boss 通关代替。

同一进程对先执行十项 LANBOT 行为检查，其中大便、普通火堆、红火堆分别用岩石墙和唯一通道验证原生眼泪破坏、穿过通道和拾取资源；大便还要求首次发射不晚于十个原生游戏帧。该场景可以布置位置和网格，仅用于定向回归；随后由原版新开贪婪局，挑战本身不复用这些夹具效果。

第一轮 `artifacts/lanbot-greed-native-r1-20261011` 在第一层完成原生 Boss 波次，客机死亡后由原版复活，但主机被大便卡住、客机反复进入商店。用户观察与日志一致，提前终止用于修复；这轮不作为通关、完整挑战或正常退出验收。客机退出码 0，主机窗口关闭未完成而被限定 PID 的工具强制退出（FFFFFFFF）。隔离档案恢复成功。重启原因是修复后需要重新加载 DLL 内嵌 LANBOT 代码。

第二轮 `artifacts/lanbot-greed-native-r2-20261011` 完成第一层 Boss 波次，两名角色均原生购买钥匙，客机也原生补血；但路线意外购买付费道具，随后出现主动道具交换循环，因此提前终止修复。先关闭主机再关闭客机，两者退出码均为 0，堆观察无新增转储，隔离档案恢复成功。该轮不作为完整挑战结果；重启用于加载修复后的内嵌代码。

第三、四轮集中回归在八项行为检查的最后一项发现大便仍未被射击，未进入贪婪挑战。第三轮结束后调整了夹具清理与生成的时序；第四轮明确记录了实际 `GRID_POOP`、State=0、Collision=3，以及 BOT 已选择 `clear_obstacle`，角色仍停在射击位置。随后将视觉半径外的射线终点改为检查原版首个命中网格：命中目标大便可射击，命中其他格子则拒绝。两轮的检查失败触发回调异常，主机被测试工具强制退出，不能记为正常退出或堆验收通过；隔离档案均恢复。第五轮需要重新加载修复后的 DLL。

第五轮 `artifacts/lanbot-greed-native-r5-20261011` 记录射线 `first_hit=66`，大便 `target_index=67`，仍未射击。J460 返回点位于阻挡网格前的空格，直接比较返回点的网格不足以判定。观察模块改为从该点沿射线采样至多一个网格宽度，以第一个实际阻挡泪弹的网格判定，不能跳过其他岩石或大便。该轮未开始贪婪挑战，检查失败后的主机强制退出也不算退出验收；隔离档案恢复成功。第六轮需要加载此修复后的 DLL。

第六轮 `artifacts/lanbot-greed-native-r6-20261011` 通过八项行为检查：大便被两颗原生泪弹打碎，State=1000，随后拾取后方心，血量 10→12。贪婪挑战在 272.375 秒判为 `stalled`，停在第一层 Boss 波次 10；两名角色共发射 111／109 次泪弹，血量下降次数 2／4。双方各启动一个进程、各在其中新开两局，最终退出码和堆观察均为 0，无新增转储，隔离档案恢复。`passed=true` 表示完整记录并清理，`cleared=false` 表示没有通关。用户再次观察到商店循环，以及火堆未识别、清障响应偏慢；据此补充大型房间标识、明确阶段机和上述障碍回归，第七轮需要加载更新后的内嵌模块。

第七轮 `artifacts/lanbot-greed-native-r7-20261011` 大便清障首次射击在第 2 个原生游戏帧，约 0.067 秒。两个火堆场景在射击后仍显示 1 HP，被观察模块继续视为燃烧目标，角色没有拾取后方心；贪婪挑战尚未开始。原版熄灭火堆保留 1 HP，随后将该灰烬状态从目标和危险区域中移除。离线模型补充正血量灰烬，实机还要求原生熄灭后安全穿越且伤害次数不增加。该轮失败后的主机强制退出不作为正常退出验收，隔离档案恢复；第八轮重新加载更新后的观察模块。

## 最终一轮验收

第八轮 `artifacts/lanbot-greed-native-r8-20261011` 使用一对主客机进程，先执行十项行为检查，再由原版新开一局贪婪挑战。十项检查全部通过：大便、普通火堆、红火堆均在第 2 个原生游戏帧开始射击，各发射三颗实际泪弹后清除障碍、通过唯一通道并拾取后方心；两个火堆场景的伤害次数均为 0。

实机同时确认大型商店的门目标为 `71`，实际进入后的索引为 `70`，两者的 `SafeGridIndex` 均为 `70`。规范化房间节点与每层阶段机生效后，主客机分别完成必要补给，均获得一把钥匙；客机在商店花费三枚金币补回受损的一点血量。两名角色的道具数量始终为五件（以撒初始 D6 加指定四件道具），随后正常进入第二层。主机转换日志为 `fight → supply → gather → leave → fight`；客机完成集合时，主机已通过原生出口触发换层，因此直接记录新层 `fight`。

挑战最终在第二层第八波以 `stalled` 结束：真实耗时 363.219 秒，原生模拟时间 348.767 秒，两名角色发射 157／177 次泪弹，血量下降次数为 0／3，未触发原生结局。最后三分钟没有有效战斗进展，日志中主要为 `kite` 任务，射击输入计数停止增长。这是尚未解决的战斗站位／射击决策停滞，阶段保持 `fight`，不是再次进入商店的补给循环；具体敌人配置尚未逐个记录，不能据此声称已经定位到某种敌人的处理错误。第一层补给和换层通过不代表全贪婪路线通关。

结果文件中 `passed=true`、`lanbot_behavior_passed=true` 表示行为检查和挑战观察、清理通过，`lanbot_greed.cleared=false` 明确表示未通关。主客机退出码均为 0，堆观察退出码均为 0，无新增崩溃转储，隔离档案恢复通过；这轮没有观察到堆损坏，不是无内存泄漏的证明。测试 DLL SHA-256 为 `8119bdb09c8da32450c755bdedfaf44dc8cae8ccb7df4dcad0b8491dc4007a17`。

本次离线检查通过 55 项 Linux CTest、25 项 Windows Lua CTest、77 项 LANBOT Lua 检查，以及 115 项 pytest 和 19 项子测试。Windows x86 Release 构建、格式、脚本语法和差异检查通过；Python 报告保存在 `artifacts/lanbot-greed-offline-r7-20261011/pytest.xml`。最终火堆灰烬修正后再次通过 LANBOT、挑战／通关夹具及 Windows Lua 回归，再进入第八轮实机验收。
