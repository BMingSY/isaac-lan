# LANBOT 的贪婪模式挑战

目标是回答真实战斗能力问题：普通贪婪模式，两个以撒角色，各自开局获得一个圣心和三个衣架，两个本机控制器都由生产 LANBOT 的 `run` / `balanced` 策略托管。种子为 `YV03 9KQF`，本机双实例延迟设置为 10 ms。初始道具以外的免费资源允许通过原版拾取；贪婪商店允许通过原生拾取购买缺少的钥匙、恢复用心及预算内有收益的被动／跟班道具；不自动交换或使用主动道具。

## 模块与流程

- `lanbot/observe.lua` 在本机房间视图读取模式、楼层、波次、按钮动画和门。挑战模式继续等待 `unsupported_run`。
- `lanbot/terrain.lua` 只把原生 `Off` / `OffSkull`、State=0、清空房间且尚未完成 Boss 波次的贪婪按钮作为目标。普通模式 Boss 波次上限为 10，贪婪困难为 11；第七层不使用该按钮策略。
- `lanbot/greed.lua` 保存每层的“战斗 → 补给 → 收集道具房 → 集合 → 离场”状态。前六层完成 Boss 波次后进入补给，商店没有可购买的目标、离开商店或补给持续不可达时进入收集道具房阶段；完成当前钥匙预算可达的道具房后才进入集合；在出口等齐队伍后离场。已经完成补给的楼层不会重新进入商店补给阶段，新楼层重新开始。`status` 和转换日志带阶段、原因与当前目标。
- `lanbot/planner.lua` 启动贪婪按钮前等待存活队友进入房间。集合与离场阶段只选已知出口及原生贪婪出口门，避免费用需求、未知分支每帧重新竞争。按钮变红时观察模块把它加入避让区域；Boss 波次后也保护可选的恶魔奖励按钮，避免误启动奖励波。
- 观察模块记录未破坏大便及贪婪商店的钥匙／心价格，规划模块只在真实路线被堵时选择需射击的大便。推测路线临时允许大便格，仅用于识别挡路目标；实际移动仍使用原始碰撞图，必须等原版眼泪碰撞打碎后才可通过。已知商店按缺钥匙／缺血和实际价格重新评估，避免因过期资源需求反复进店。
- 付费物品同时作为碰撞避让区域，只有选中的钥匙／恢复用心／道具开放通行，防止寻路途经其他商品时发生原生购买。已有主动道具时避让地上主动道具，防止新旧道具反复交换。
- 观察模块把入口占格索引归并到带维度的 `RoomDescriptor.SafeGridIndex`，门的目的地、已访问节点和队友位置使用相同标识。大型商店从不同入口进入时仍然是同一个房间，避免当作尚未探索的分支；API 差异见 [RoomDescriptor 文档](https://wofsauge.github.io/IsaacDocs/rep/RoomDescriptor.html#safegridindex)。
- 前进直线上处于射程内的大便／可射击火堆在当前决策就进入清障，不等寻路失败或卡住计时。普通与红火堆通过正常泪弹熄灭，蓝火和紫火保留避让区。实际移动必须等原生碰撞／火堆生命值表明障碍已消失，不能直接穿过火焰。
- 寻路、避险与射击沿用原有 LANBOT，通过正常控制器输入触碰按钮、门、地板出口和结局箱。不写波次，不调用按钮 `Reward()`，不改伤害或世界状态。按钮 API 参考 [Lua API 文档](https://wofsauge.github.io/IsaacDocs/rep/GridEntityPressurePlate.html)。

贪婪策略在 `src/bridge/lanbot.lua` 和 `src/bridge/lanbot/`；本次进门修正属于前述房间生命周期及最小原生适配。联机同步字段和协议不变。贪婪困难的波次边界有离线覆盖，本次实机挑战只验证普通贪婪模式。

## 公平性与结果

`tests/state_lanbot_greed.lua` 仅在第一层、波次 0 时为主客机各增加指定四件道具，并核对数量。血量、伤害、射速和移速由原版道具效果决定。没有免伤、持续回血、自动复活、敌人冻结、清怪、额外赋予道具、瞬移、脚本换层或修改眼泪伤害。实际开局属性和两名角色的血量下降、死亡／原版复活、射击数、波次、楼层均写入日志。

最终 `RESULT` 区分 `win`、`death`、`stalled`、`timeout`。只有第七层的原生 `MC_POST_GAME_END(false)`，以及第一至第七层、前六层 Boss 波次、Ultra Greed 和两名角色的实际射击证据都齐全，才记为通关。队伍死亡或三分钟未推进也能完成一次有效试验；工具的 `passed` 表示夹具正常完成并清理，`lanbot_greed.cleared` 才表示挑战成功。BOT 决策异常另记 `bot_error`，结束夹具并报告整体失败，不用回调断言阻止正常关闭；主客机错误清理与判定有离线覆盖。

离线生命周期模型直接执行这份夹具，禁止额外道具、位置／血量写入、免伤、瞬移、伤害和射击代写，并覆盖主客机通关、死亡和卡住的清理路径。单个种子的成败不能代表全部随机种子。

## 执行

先完成离线检查和 Windows Release 构建，然后使用一个隔离主客机进程对。结束后恢复隔离档案，并检查退出码、堆观察结果和新增崩溃转储。

```sh
.deps/checks/bin/python tools/run_special_routes.py \
  --host /mnt/d/isaac-lan-lab/host-001 \
  --client /mnt/d/isaac-lan-lab/client-001 \
  --build build-win32 --output artifacts/lanbot-greed-native-r16-20261011 \
  --case lanbot --case lanbot-greed --latency-ms 10 --port 30990 --heap-check
```

第十六轮已经完成短步与刹车、队友分配和正常结局验收；此前商店、入口和结局问题及逐轮失败记录保留在下文。通关判定以实际原生结局为准。重复执行时使用新的输出目录，保留既有证据。
