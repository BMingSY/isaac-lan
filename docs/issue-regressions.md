## 修复范围

- 存档：保留本机进度基线直到原生退出保存结束；已有单人继续存档无法备份时拒绝联机开局。联机继续按角色顺序重新绑定控制器，避免物理设备编号变化导致玩家丢失。
- 房间与角色：资源修改、幽灵转换和道具产生的效果在角色自己的房间及角色集合内执行；幽灵跟随存活队友，Dark Esau 在原生离房清理与目标房间初始化之间保留。
- 战斗与输入：进入已有战斗房间时重新关门；Boss 战斗期间保持下一层入口关闭；客机实际结束入场动画后才恢复该房间模拟；换房时仍保留暂停／返回输入。
- 客机呈现：即时删除旧网格后再建立替换网格；保留多节怪引用和身体层位置；同步生成房间的描述符、地图格索引和未拾取物元数据。地图临时借用的实体数组在缓存完成后立即恢复。
- 传送与结算：区分普通传送离场动画和原生传送门后续动画，恢复到达角色的操作；按各房间模拟推进闪屏计时，避免百变怪死亡流程一直等待计时归零。

协议版本由 21 更新到 22，状态快照格式更新到 8；联机双方需要使用本次构建。

### Steam 启动错误 11

用户从 Steam 启动正式安装后反馈初始化 code 11。该错误对应继承的 `ISAAC_LAN_LAB_ROOT` 与当前可执行文件路径不符；原判断把另一目录的正式游戏也当作隔离实例。现在只有路径吻合且具有隔离标记的实例才启用存档重定向。具有正式安装标记的其他游戏忽略残留隔离变量；未安装的陌生路径仍拒绝启动，缺少标记的隔离实例也不能回退到真实存档。

- 离线 C++／Lua 21 项检查通过，新增回归覆盖正式启动、继承外部隔离变量、真实隔离实例和缺少标记的拒绝行为。Windows 构建及 Windows 版新增用例通过。
- 本轮只检查启动、隔离范围和构建指纹，没有注入游戏操作或自动创建房间。Steam 版在带有外部隔离变量的环境下记录 `startup_lab_environment=IGNORED`、`isolation=installed` 与前端 READY；隔离实例保持 `isolation=profile_redirect`。两端构建指纹一致。
- 重启原因：Steam 原进程初始化失败并退出，需要安装修复后重开；随后隔离实例需要重新加载相同 DLL，否则强制构建指纹会拒绝连接。更新隔离实例时保留 Steam 进程。

### 单人 Mod、过房蓄力与 Stats+ 玩家缓存

2026-10-10 根据用户进一步反馈修复三处问题：

- 普通启动没有全局 `debug`，联机桥接在拦截 `RegisterMod`／`require` 时却直接使用它，导致其他 Mod 加载失败。现在由原生层提供私有的源码与 upvalue 检查函数，兼容适配使用这些函数，保留普通模式的全局沙箱。新增 `bridge.mod-loading` 离线用例覆盖没有全局 `debug` 时的注册、模块加载、错误传递与私有检查。
- 客机硫磺火过房自动发射有两条输入过滤路径：主机拒绝来源房间不匹配的输入；客机在原生房间加载期间没有完整的房间上下文。两处都会清零射击值，合成一次松键。现在同层换房保留持续射击值，并在加载期间沿用最后有效的同层房间上下文；移动、道具与射击边沿仍过滤。真实松键正常传递，换层不沿用旧房间输入。新增 `core.transition-charge` 覆盖这两条路径、真实松键与换层隔离。
- Stats+ 在联机视口就绪前可能缓存两名玩家，补充数值的渲染继续读取旧缓存。现在过滤缓存中的远端玩家，等待容器与生命周期模块加载完整，再按本机玩家与逻辑索引 0 重建缓存。通过 `GetPtrHash` 比较原生角色身份，避免新 Lua 包装对象造成逐帧重建。离线覆盖旧缓存、延迟导出、角色包装变化与未联机的原版双人行为。
