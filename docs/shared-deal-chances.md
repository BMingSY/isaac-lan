# 全队共享恶魔房／天使房概率

恶魔房和天使房的概率属于整队。房主使用全队的原版道具、饰品、受击、交易和楼层历史计算；客机使用房主的计算结果。玩家分处不同房间时也适用。增加和降低都影响同一份概率，多个玩家的 HUD 百分比不会直接相加。

保留原版的叠加和优先级：例如多个五芒星可以增加原版允许的额外概率，重复羊头和相同钥匙碎片不会凭空叠加；圣体、忏悔书、美德之书及楼层天使修正仍按原版判定。房间类型已经被原版确定后，不重新抽签或改写已有房间。星象房不在这次改动范围内。

## 模块与同步契约

- `src/bridge/sync/deals.lua` 采集、校验和应用整队概率；`app/world.lua` 仅装配组件。顶层元组新增第 19 项 `deals = { total, angel }`，schema 12 → 13。`total` 是原版总开门概率，可超过 1；`angel` 是原版条件天使房概率，范围 0–1。通常显示的恶魔／天使概率分别为 `min(total, 1) * (1 - angel)`、`min(total, 1) * angel`；原版仍处理不允许开门的楼层和双重性显示。
- `src/compat/items/deal_chances.h` 接收各原版查询的普通浮点数，合并跨房间效果；同一份全队库存与楼层惩罚不会因查询多个房间而被重复累加。
- 客机在库存应用后保存该结果。原版 HUD 的两个概率查询读取同一份已应用结果，客机不因本地受击记录或道具恢复副作用自行重算。楼层屏障、新局和原生楼层清理清空缓存；旧代次状态不能应用到新楼层。
- 只新增两个浮点数，不逐个同步概率道具或复制道具给房主。传输协议仍为 24；握手的扩展 DLL 指纹要求两端同构建，schema 13 同时拒绝旧布局。

## 必要的原生能力

现有 Lua API 不能让实际恶魔／天使房生成临时读取分房后的完整玩家名单，也不能覆盖原版 Found HUD 使用的内部条件天使概率。因此在 J460 后端提供具名 `deal_chances()` 查询／应用与 `deal_chances_reset()` 清理能力，并给原版四个入口补充范围限定的上下文。没有在后端重新实现道具公式或修改战斗模拟名单。

使用原版 J460 1.9.7.17 可执行文件（SHA-256 `7122ac28779925b24e23e2416f231322b1470388bd25e2c08665ad8d53b3ea4f`）的 Lua 绑定、实际调用点和反汇编核对：

| 入口 | RVA | 用途与 ABI |
| --- | --- | --- |
| `Room::GetDevilRoomChance` | `0x3f92b0` | Lua 公开查询、HUD 和实际开门共用；`thiscall`，x87 返回 |
| 原版条件天使概率查询 | `0x3f96f0` | HUD 与房间类型初始化共用；无参数，XMM0 返回 |
| `Level::InitializeDevilAngelRoom` | `0x3499a0` | 决定实际生成类型；`thiscall(bool, bool)` |
| `Room::TrySpawnDevilRoomDoor` | `0x3f83b0` | 原版清房开门及公开 API；`thiscall(bool, bool)` |

四个入口均加入启动签名校验。条件天使查询的内部 SSE ABI 在后端通过单独的桥接函数处理，普通 C++／Lua 浮点接口仍使用正常 ABI；Release 对象反汇编核对了 x87 → XMM0 的返回桥接。

具名概率查询也通过这两个真实原版入口和 SSE 返回路径读取，专项用例因此检查 HUD／实际生成所使用的入口，而非仅检查独立的 Lua 缓存读取函数。未启用联机会话时，原版入口维持单人规则。

概率查询和房间类型初始化短暂借用现有 `TeamScope` 的完整名单，退出后恢复原来房内名单；不移动角色，不运行额外实体更新，不分配或释放原生对象。实际开门只在房主执行。

原版额外的 Boss 房红心受击惩罚依赖当前房间。查询时，如果已加载本层原版指定的最终 Boss 房，短暂借用其 Room 指针、房间索引和维度，随后恢复，确保玩家走出 Boss 房不会隐藏该惩罚。只读取既有房间，不加载 Boss 房、不消耗生成 RNG、不改写受击记录。其余受击、交易、乞丐和捐款等楼层状态沿用房主已有的全局原版状态。

原版部分临时保证开门效果保存在 Room 中。用相同的全队／Boss 惩罚上下文查询已有房间对象，取原版已经计算的最大总概率，从而让异房保证效果也对整队生效；不把同一效果相加，不复制效果，不延长原版对象生命周期。该处理仅适用于原版总概率查询已经识别的房间效果。

API 仅允许客机写有限、非负且可表示为 float 的总概率和 0–1 的条件天使概率，先整体校验后更新一对值，不允许房主接收客机概率。缓存只保存数值，不保存原生指针。规则依据以实际 J460 调用链为准；[Room Lua API 文档](https://wofsauge.github.io/IsaacDocs/rep/Room.html#getdevilroomchance) 用于核对公开查询的含义，旧 Repentance 的示例公式不直接移植到 Repentance+。

## 验证

离线检查包括跨房间保证效果的去重、概率二进制往返、重复应用、保证概率超过 100%、非法值、换层清理，以及普通／困难／贪婪／超级贪婪模式的生产世界采集与应用链路。54 项 Linux 离线 CTest、79 项 Windows Release CTest、111 项 pytest 和 19 项子测试通过；Python／Lua／组合夹具语法及格式检查通过。

`tools/run_special_routes.py --case shared-deals` 在一组隔离主客机中逐项检查：异房五芒星与原版叠加、移除道具、客机在普通房和 Boss 房实际红心受击、忏悔书、交易历史、异房钥匙碎片与去重、美德之书、正负楼层天使修正、异房羊头与去重、原版 Boss 死亡生成恶魔门、换层后异房圣体生成天使门。客机对每份已应用状态核对公开总概率查询和内部条件查询。可在同一次进程启动后继续 `--case campaign` 检查原版换层与结局，并启用 `--heap-check` 检查干净退出。

专项夹具冻结在 `artifacts/shared-deals-native-r4-20261011/`，被测 DLL SHA-256 为 `349e6c24c7bc1b0c8044a3a3613c2e99622ba6b795162bd975cf28e0eab9b661`。主客机共享概率专项已通过，实际门类型在房主清 Boss 后检查，客机逐份快照检查概率一致。下表是原版查询的原始浮点数，HUD 仍将总概率限制到 100%。

| 实机检查 | 结果 |
| --- | --- |
| 异房客机五芒星；再增加房主五芒星 | 总概率 `1.35 → 1.45 → 1.50` |
| 客机普通房实际红心受击；客机忏悔书 | 总概率 `1.35 → 0.36 → 0.76` |

前三轮 `r1`／`r2`／`r3` 未通过验收：分别是夹具直接执行控制台换层绕过可靠楼层事件、进房保护期间强制受击被拒绝、忏悔书移除后留下的永恒心使红心计数没有减少。修正夹具为既有 `SetStage + StartStageTransition` 路径、等待真实红心变化，并在受击夹具中清理额外永恒／魂心。异常已使会话结束，工具随后强制关闭该轮隔离游戏，两端退出与堆监视均不能作为通过证据；各轮原始失败日志和配置恢复记录保留。`r4` 完成共享专项后在同一组进程继续通关回归。

最终 `report.json` 的 `shared-deals`、`campaign` 两项在主客机均通过，`passed=true`、`restored=true`。通关记录覆盖第一层至第八层、阴间（10）、暗室（11），两端收到原版 `MC_POST_GAME_END(game_over=false)`，客机应用了 6311 份通关快照。复用同一组进程（房主 5232、客机 36760），总耗时 449.78 秒；两端正常退出 `00000000`，堆监视退出码均为 0、新增转储均为 0，冻结日志无 `Caught exception`、`Error in` 或 `LAN_NETWORK FAILED`。被测 DLL 与当前构建哈希一致。

本轮堆监视证明该流程未检测到堆异常，不代表排除了所有泄漏。结果以冻结的 `engine/host/log.txt`、`engine/client/log.txt` 和 `engine/result.json` 为准；工具结束后会恢复旧的 lab 日志，不用恢复后的 live 日志判断这次测试。
