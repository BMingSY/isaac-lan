# 分房模拟与本机显示

## 房间不是全队共用的当前视图

原生游戏有一个进程级当前房间及相关全局数据。分房联机保留共同楼层，但为每个有人活动的房间保存上下文，按顺序调用原生更新。这里的同时战斗是同一游戏时间内依次推进多个房间，不是多线程调用游戏对象。

房间键为 `(dimension, roomIndex)`。镜像层和其他维度不能只按房间索引区分。

[`engine_rooms.cpp`](../src/engine_rooms.cpp) 中的 `Scope` 临时切换房间指针、相关标量、房间玩家名单、伏击状态、渲染资源和音频上下文，退出时恢复外层上下文。

## 所有权与更新

- 原生容器、精灵和镜头保留游戏内的所有者。MinGW 的 C++ 对象不能作为游戏的 MSVC STL 对象传入或交给游戏析构。
- 进程级的房间渲染缓冲区随房间交换完整引用所有权。只换房间指针会使大小房间共用不匹配的阴影或后处理资源。
- 原生角色形态变化可能替换角色对象或修改名单。退出房间作用域时，需要把这些变化合回完整名单，不能继续使用过期角色指针。
- 房主更新所有有在线玩家的房间；最后一名玩家离开后，房间通过原生 `RoomDescriptor` 保存并卸载。再次进入走原生初始化。

客机只初始化和显示自己的房间。其他房间里的队友使用不运行玩法、不加载背景的存储壳，保留多人 HUD 所需的角色状态。

## 过门与汇合

1. 原生过门或传送产生目标房间请求。
2. 在当前房间作用域退出后处理迁移，执行原生角色离房清理。
3. 把角色及其跟班等随行实体迁移到目标房间。
4. 目标未加载时走原生房间初始化；目标已有玩家时保留现有实体，只执行新进入者的进房效果。
5. 按对应门口放置角色，恢复前景上下文并处理空房间卸载。

额外进门无敌只用于进入已有其他在线玩家正在战斗的房间。普通探索过门不因此获得保护；原版本身的保护机制仍由游戏执行。

客机显示的门由房主同步槽位、目标索引、房间类型、锁状态和精灵。只同步网格动画而漏掉原生门槽位，会出现门不可见、可穿越或访问错误。

## 本机视图与原生 HUD

游戏模拟的完整玩家名单与界面暂时看到的名单有不同用途。`withView` 为绘制切换到本机房间，把本机控制器的角色放在显示名单前面，绘制完成后恢复名单。

| 内容 | 归属与实现 |
| --- | --- |
| 房间、背景、镜头与地图焦点 | 本机角色所在房间；镜头使用该房间的原生镜头对象 |
| 血量、卡牌与主动栏 | 保留原版多人 HUD，并保持本机栏位归属 |
| 属性栏、道具列表与拾取提示 | 本机控制器对应的角色 |
| 小地图玩家位置 | 共同楼层中的在线玩家位置 |
| 地图放大与 Mod 界面操作 | 本机物理输入，不能使用队友的网络操作 |

换层期间可能尚无可显示房间，仍通过临时显示名单维持本机 HUD 归属。该排序不能改掉玩法使用的控制器编号或存档人数顺序。

## 表现也需要归属

表现不能全部广播给每个人。客机进入 Boss 或贪婪房，只通知该房间的观看者，不能接管房主的全局过场。

音效和 Boss 播报按房间观看者筛选，并带有事件序号；客机去重、过滤过期事件，Boss 播报还会核对所在房间。音乐从本机房间的原生音乐状态恢复。角色动画、装扮和蓄力精灵使用房主采集的状态，在渲染边界重新应用。

音乐缓存使用 `(floorEpoch, dimension, roomIndex)`，防止下一层复用房间索引时继续播放旧曲目。尚未记录曲目的房间通过原生选择器补采集一次，覆盖开局先于联机初始化播放音乐，以及多个房间使用相同曲目而原生跳过 Play 的情况。客机重放音效时进入自己角色的房间作用域；本地原生播放也按观看者过滤，避免前景房间仍指向主机时串音。

卡牌、药丸和道具的拾取／使用提示，以及书类道具的全屏演出，只交给触发角色的控制器观看；同房间的队友也不会收到这些界面动画。房主发送有界的原生演出事件，客机只播放界面，不再调用 `UseCard`、`UsePill` 或 `UseActiveItem`。事件带序号和楼层 epoch，重复快照、过期事件和旧楼层事件不会重新播放。

房主为每个控制器保留独立的原生 ItemOverlay，每个权威更新推进动画，仅把本机控制器的对象绘制到房主视口。使用全局 ItemOverlay 会暂停整个 Game 更新，让另一位玩家同时按下的道具操作丢失；独立对象避免这类全局暂停和演出互相覆盖，也保留 Mega Mush 动画结束后恢复角色可见性的原版行为。额外对象通过游戏自身的构造、配置加载和析构入口管理。

客机除了去重后的触发事件，还接收 ItemOverlay 的状态、延时及完整的普通／Mega Sprite，包括图层、贴图和帧。只重放 Show 不能恢复卡牌的文字图层和书类道具画面。客机不执行 ItemOverlay 的原生 Update：该函数会在动画标记处治疗角色、换房和播放音效，这些行为只由房主执行，客机应用同步后的画面。

客机实体不运行原生战斗更新，因此还需要显式同步阴影、激光路径和部分精灵层状态。原生会把某些效果烘焙到背景；客机清理和标志处理需要避免旧实体留下永久黑影。

后台房间初始化对进程级色彩、过场纹理或渲染标志的写入，也要在本机显示前恢复。是否恢复正确必须通过队友正常过门时的连续画面验证。

## Mod 回调与输入

当前对全局 `MC_POST_NEW_ROOM`、`MC_POST_UPDATE` 入口限定本机房间上下文，避免队友换房更新本机地图缓存。房主的实体、伤害等玩法回调仍在对应权威房间执行。

渲染和本机 UI 使用 `input::ViewScope` 读取本机物理输入；地图操作也单独按本机输入查询。角色战斗更新使用房主消费的对应控制器输入。

Good Trip 等本机界面发起原生换房时，客机发送 `RoomRequest`，房主核对源楼层、源房间、维度和在线身份后执行。请求描述意图，不允许客机提交任意世界状态。

依赖全局换房回调的第三方玩法 Mod 在队友房间可能效果不完整。当前没有复制任意 Mod 私有状态的机制，也不为每个 Mod 改写内部逻辑。
