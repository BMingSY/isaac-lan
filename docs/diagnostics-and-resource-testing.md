# 配置、诊断与资源回归

配置解析及有界统计规则在 `src/core/`，配置文件读写在 `src/app/configuration.*`，日志和进程测量在 `src/diagnostics/`，Lua 同步阶段计时在 `src/bridge/diagnostics/`。网络模块只提供通用传输资源计数和压缩／解压耗时观察接口。原生游戏对象仍由版本后端管理。

## 配置及分局日志

游戏目录的 `isaac-lan/config.ini` 首次启动生成，已有文件不重写；使用 UTF-8，支持 BOM、CRLF、空行及以 `;`／`#` 开头的注释。键名及值区分大小写，不支持行尾注释。重复键保留第一次赋值；未知键、非法值在启动日志中记录，非法值回退到对应默认值。文件超过 64 KiB 时整份回退。

默认 INFO 日志、关闭性能统计、采样间隔 1000 毫秒。DEBUG 日志可显式启用。修改需重启；诊断选项不决定玩法或同步字段。安装器只管理安装清单，不覆盖用户配置。

原版日志目录通过原生 `log.txt` 打开路径确认，支持自定义存档路径。日志结构为：

```text
isaac-lan/logs/20261011-120000-123-p1234/
  startup.log
  001-YV039KQF-host/runtime.log
  001-YV039KQF-host/performance.jsonl
  002-YV039KQF-client/runtime.log
```

启动时间和 PID 区分进程，同种子重开／继续用新的序号。退出一局后恢复写启动日志，保留退出清理证据。没有自动删除、轮转或总量限制。输出句柄随目录切换关闭，错误日志立即刷新；启动路径确认前只保留最多 256 KiB 的迁移缓存。

## 性能证据

`performance.jsonl` 每个采样窗口记录：

- 相对本局时间、窗口时长、进程 CPU 占单核比例、私有内存、工作集及句柄数；读取失败为 `null`。
- 渲染回调间隔；完整采集／应用、编码／解码、库存、实体、网格、精灵及压缩／解压耗时。
- 本机 Lua 堆大小、实体／网格／地图规模、网络连接、发送队列及接收／待发状态容量、退休会话数量。

耗时记录数量、平均值、最大值及 p50／p95／p99；百分位使用每个窗口最近 512 个样本，均值及最大值使用该窗口全部样本。成本名和计数器各最多 64 个，窗口重置，避免诊断本身无限积累数据。Lua 堆测量只读 `collectgarbage("count")`，不强制游戏 GC。关闭统计时 Lua 直接调用原函数，不包装返回值。

```sh
python3 tools/check_performance.py artifacts/my-run --output artifacts/my-run/summary.json
```

报告列出资源起止／范围、按调用次数加权的平均耗时及最慢窗口的百分位；不会把多个窗口的百分位当作全局百分位。游戏加载资源、换层和不同怪物规模都会影响内存，单纯全流程首尾差值不能证明泄漏。定位客机卡顿应对照帧间隔、应用成本、队列和对象规模；堆调试和画面录制会改变性能，需单独运行正常性能采样。

## 离线及 CI

Linux CI 显式启用 ASan／LSan／UBSan，保留 CTest JUnit 和 Python 回归报告。LSan 检查退出时不可达的分配；仍可达但持续增长的缓存由生命周期测试检查。

- Lua：生产实体协调模块反复创建／删除 32 个互相引用的实体，1000 轮；重复快照不多创建实体，清空后弱引用释放，强制测试 GC 后堆增长小于 64 KiB。
- Windows x86 传输：预热后重复建立 40 轮会话，包含慢消费者和状态合并；要求队列／状态容量有界，关闭后连接及队列清零，私有内存增量不超过 8 MiB、句柄增量不超过 2。
- Windows 日志／指标：重复 40 局及 40 万次计时样本，要求关闭后句柄回到基线；检查 DEBUG 过滤、同种子分局、失败切换保留原日志及关闭诊断时无指标文件。

Windows CI 保留资源测试输出；异常退出、资源超限和 sanitizer 错误均使检查失败。这些测试不覆盖游戏自身或未执行的原生 Hook。

## 第一层至结局与堆调试

完成构建及离线检查后，可在两个已标记的隔离实验目录运行：

```sh
python3 tools/run_special_routes.py \
  --host /mnt/d/isaac-lan-lab/host-001 \
  --client /mnt/d/isaac-lan-lab/client-001 \
  --case campaign --performance --output artifacts/campaign
```

`campaign` 在第一层开始，以加速夹具进入原版生成的 Boss 房，保护角色并提高攻击伤害。怪物战斗、掉落、负片拾取、出口碰撞、楼层生成、羔羊结局及进程退出仍走原版链路。主客机都必须观察到 1–8、10、11 层和原版胜利回调，客机还核对换层屏障、权威状态及本地解锁进度恢复。无控制台换层或直接结束游戏。固定种子及路线前置解锁属于显式夹具；不代表所有随机路线验收。

默认不录制画面，`--record` 按需开启。其他兼容场景可在 `campaign` 前用多个 `--case` 合并，同一对进程依次验证。包装器备份并校验恢复隔离目录的 profile、游戏存档及配置目录，不访问正式 Steam 存档；退出结果非零时，即使局内断言通过，整体仍失败。

路线进度夹具在启动前写入隔离目录的原版 `persistentgamedata1.dat`，启动后只读核对；不能在角色菜单初始化后修改内存中的解锁表。`tools/progress_fixture.py` 限定 J460 文件头、成就／计数器区段和原版校验算法，保留其余区段及不透明版本字段，校验不匹配直接失败。写入使用同目录临时文件和原子替换，结束后由包装器恢复原始存档。必须先有该版本生成的原版基线文件。

`--heap-check` 使用 `isaac_lan_heap_watch.exe` 在独立进程中观察已验证路径的隔离游戏。游戏现有异常入口将寄存器及异常记录复制到仅用于实验环境的共享区，等待外部观察器完成完整内存转储后，继续交给原来的异常处理链。观察器核对隔离标记和进程路径，不修改 IFEO、注册表、游戏原生对象或 Steam 设置；不附加调试器，避免本环境中调试启动造成的 Steam 初始化失败。

最多采集前三次访问异常／堆异常／栈缓冲区异常，异常线程最多等待 30 秒；默认无观察器时不等待。关闭夹具给正常清理和完整转储预留 45 秒，超时强制终止必须判失败。完整转储可能较大，保存在验收产物的 `heap-dumps/`，不打入用户安装包。绕过 vectored handler 的 fail-fast 或游戏更早的启动错误不保证被采集，仍以进程退出报告判失败。没有观察到异常不能单独证明间歇堆损坏已经修复。

转储先写观察器所在 Windows 的临时目录，再复制到产物目录，避免跨 WSL 文件系统的写入延迟拖住游戏异常线程。复制失败保留临时转储并报失败；并发异常只允许一个线程占用上下文，等待超时后继续保留占用，避免覆盖仍在读取的记录。观察器及合成夹具均支持游戏超过 2 GiB 的虚拟地址空间。

Windows CI 使用独立的合成进程触发 `C0000374`，验证上下文通知、完整转储和非零退出报告；该夹具不启动游戏，也不声称重现真实堆错误。合成转储在检查后删除，只保留检查报告。

堆错误根因和本次实机验收见 [堆损坏回归记录](heap-corruption-regression.md)，不由工具存在或离线通过推定已修复。
