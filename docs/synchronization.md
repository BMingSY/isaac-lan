# 网络与状态同步

## 三类数据

| 数据 | 方向 | 内容 | 处理原则 |
| --- | --- | --- | --- |
| 输入与请求 | 客机 → 房主 | 移动、射击、主动等输入，共享控制命令、本机 Mod 发起的换房请求 | 房主按玩家归属处理；连续输入取最新值，按下边沿保留到消费 |
| 实时视图 `WorldState` | 房主 → 对应客机 | 全队主要角色状态、地图、本机房间实体与网格、音画表现 | 独立完整视图；尚未开始发送的旧视图可被替换 |
| 可靠事务 | 双向控制，以房主发布为主 | 大厅、开局、检查点、换层、回退、加载就绪和结束 | 按协议顺序完成，不能当作过期视图随意丢弃 |

[`net/protocol.h`](https://github.com/BMingSY/isaac-lan/blob/main/src/net/protocol.h) 中的 `Frame` 是房主内部汇总本次操作的结构。客机不接收它来计算相同玩法结果。

## 输入采样与消费

[`runtime/session.cpp`](https://github.com/BMingSY/isaac-lan/blob/main/src/runtime/session.cpp) 按原生输入／渲染帧采样客机输入，正常为 60 Hz；同一帧内的多次轮询只采样一次，发送后立即轮询套接字。房主在每次原生模拟步骤前采样本机输入，不再用独立的墙钟定时器限制模拟。原生完整更新仍为 30 Hz，半帧逻辑保持原有顺序。每份输入包含 16 个量化动作值和按下边沿位图。

客机显示预测每次渲染读取最新持有值，不等待下一次网络采样。这次读取不消费按下边沿；主动道具、卡牌和暂停等动作仍由房主消费网络输入后执行。

本机配置 `[network] input_hz` 支持 30／60，默认 60，启动时读取。30 档按每两个原生渲染帧采样一次，卡顿后只采当前输入，不补发过去的样本；实际频率受原生帧率限制。此项只影响本机作为客机时的输入发送，不参与构建指纹，也不改变主机模拟、快照发布或本机显示频率。不同频率的客机可加入同一房间，主机分别确认各自的输入序号。非法值回退 60 并记录配置警告，保留文件中的原值。

旧配置启动时补齐缺失的已知配置项及其说明注释，保留已有文本、值、注释与未知项；重复启动不重复追加。先写入临时文件并刷新，再检查原文件未发生变化后原子替换；写入失败时保留原文件，运行时仍对缺失项使用默认值。配置大小继续限制为 64 KiB。各项使用说明放在配置文件的 `;` 注释中。

暂停菜单方向、确认和设置由本机原生菜单消费，不进入房主玩法输入；暂停时只保留射击持有值，避免恢复时丢失蓄力。打开暂停沿用原有输入边沿，恢复和退出走可靠控制命令。实时视图只同步暂停状态和发起者，不同步菜单页、光标和设置。

房主使用最新输入继续模拟，不逐帧等待每名客机。开局第一次推进会等待初始玩家完成引擎准备；运行中的慢输入或重连加载不构成同样的全队屏障。

持续按住的动作可以复用最新值。按下边沿在下一次消费后清除，避免一次按主动被重复执行。客机超过 500 ms 没有新输入时，房主暂时使用中性输入；连接超时另行处理。

三个编号承担不同职责：

| 编号 | 含义 |
| --- | --- |
| `tick` | 房主发布状态的模拟序号，用于排序与应用回执 |
| `inputSequences` | 房主本次模拟使用的各玩家输入序号，用于移动预测确认 |
| `floorEpoch` | 换层、重建和回退事务的代次，用于隔开新旧楼层状态 |

回执表示已经应用房主状态，不表示双方进行了随机序列或完整模拟状态比较。

## 状态字段与实体身份

[`sync/world_schema.lua`](https://github.com/BMingSY/isaac-lan/blob/main/src/bridge/sync/world_schema.lua) 定义顶层字段，[`sync/capture.lua`](https://github.com/BMingSY/isaac-lan/blob/main/src/bridge/sync/capture.lua) 采集并使用自定义二进制编码。类型包括布尔、整数、有限浮点数、字符串和数组。向量、颜色与原生表现数据先转换为可传输值。

| 范围 | 主要内容 |
| --- | --- |
| 楼层 | 层数、类型、共享诅咒位掩码、贪婪波次、整队恶魔／天使房概率、地图访问／清理／显示标记、玩家所在房间与维度、药丸颜色效果与鉴定状态 |
| 全队角色 | 角色类型、属性、道具、血量、资源、主动充能、卡牌／药丸与原版口袋槽顺序、幽灵、临时形态、里小蓝人的粪便数量与队列 |
| 本机房间 | 敌人、泪弹、跟班、炸弹、拾取物、激光、效果、网格和门的状态、特殊房间返回入口、水流方向 |
| 表现 | 同房角色的身体／装扮／蓄力精灵，实体动画、阴影、激光路径、教条光束预警几何、音乐、音效和播报 |

所有角色都有主要状态，以支持原版多人 HUD；完整角色表现只采集当前客机房间里的角色。房主按客机生成视图，在同一 `(epoch, tick)` 复用公共字段、角色与房间采集；音效和演出仍逐客机处理，见[采集契约](https://github.com/BMingSY/isaac-lan/blob/main/docs/layers-and-compatibility.md#采集与副本恢复)。

实体使用房主分配的递增 ID。客机维护 `ID → EntityPtr`，先创建或更新实体，再补齐父、子、生成者和目标引用。ID 不依赖两个进程的地址或实体分配顺序。

不会传输 Lua 源码、原生指针或第三方 Mod 的任意 `GetData()` 表。实体字段要通过显式 schema 扩展；将 userdata 直接放入状态会导致序列化失败。

## 客机应用与原生更新

客机由 [`sync/replica.lua`](https://github.com/BMingSY/isaac-lan/blob/main/src/bridge/sync/replica.lua) 按[恢复阶段](https://github.com/BMingSY/isaac-lan/blob/main/docs/layers-and-compatibility.md#采集与副本恢复)应用完整视图：库存副作用后恢复共享状态，全部成功后才提交完成 tick。

客机保留原生房间清理、背景和显示所需的更新路径，但拦截实体玩法更新和门的自主决策。同步实体也关闭碰撞，避免客机再次计算伤害、拾取或门状态。流水水花（`1000.99.1`）作为纯表现由两端按房间水流自行生成、更新和销毁，不分配同步 ID；其他水花子类和玩法效果保留权威同步。房间元组第 8 项传输水流向量，在实体恢复前写入当前客机房间，补上副本布局省略初始生成标记后缺失的环境状态。

若原生换层尚未准备好，保留最新视图并延后应用。换层事件会清除旧视图和预测缓存。应用层使用还原后的完整视图；传输增量依赖明确确认的基线，不依赖已被合并丢弃的中间视图。

客机也在原生半帧边界轮询并应用快照，避免收到状态后继续等到下一次完整更新。首次视图、暂停切换、连接名单变化、换层、任一角色换房或角色替换仍在完整更新路径处理；半帧预检不执行房间／角色写入。提前应用不会额外调用原生玩法更新。内部恢复回调的可选第四参数 `betweenUpdates` 必须由包装器原样传递；返回 `false` 时保留最新快照，等待完整更新。

协议 29 在可靠 `Stage` 事务中增加有符号 16 位的 `sourceRoom`（`[-20, 168]`），供原生选层读取主机的实际入口。重连期间缓存的换层事件和回退分块一致性校验均保留该字段；世界 schema 与嵌入模块清单不变。旧协议不能连接，扩展指纹仍包含实际 DLL 内容。

## 移动预测与插值

本机角色从房主位置建立自己的移动轨迹，每次渲染按最新物理输入更新速度与位置。持合成袋及举起／收起时的行走姿态允许继续预测，制作／拾取动画和控制锁定仍会暂停预测。普通步行使用 J460 的加速和摩擦曲线，松手后在本机减速，不等待房主的位置更新。两次发送之间的实际位移归属下一份输入序号，确认时保留尚未发送或尚未消费的移动。

房主位置与对应输入确认时的历史预测位置比较，不能直接拿延迟的位置与本机当前画面比较。普通移动允许一个原生模拟周期内的误差，不逐包重置本地速度或位置；明显偏差单独平滑修正，96 个坐标单位以上的突变立即按传送重置。静止后使用更小的误差范围收敛。实现见 [`bridge/presentation/prediction.lua`](https://github.com/BMingSY/isaac-lan/blob/main/src/bridge/presentation/prediction.lua)。输入序号不是模拟帧；同一确认重复出现时不会重复消费历史。

预测处理本机房间的镜像方向、边界和网格阻挡；开门的狭窄通道允许本机显示走到门口。在过门阈值暂停预测，等待房主的新房间视图；换房前清空旧轨迹、惯性和纠偏，接收角色状态后建立新轨迹。传输输入另外携带楼层代次和房间键，房主只在对应房间消费这些输入，避免旧房间仍在传输的持有值和按下边沿在新房间继续执行。这个校验也覆盖 Mod 传送和换层。

这仍是显示预测，房主执行碰撞、战斗、拾取和换房。特殊移动道具、外力和复杂地形未进行完整原生重放，可能发生纠偏。进入新房间的内容仍需等待权威视图，无法完全消除网络和房间初始化时间。

其他实体从最新权威位置建立显示轨迹，按速度最多外推 100 毫秒，不再固定落后一份快照。新快照到达时沿用上一条轨迹在当前时刻的位置，仅将权威偏差以约 33 毫秒的时间常数平滑收敛；跳过中间快照不会重置到旧权威位置。重复 tick 不重启轨迹，96 个坐标单位以上的偏差立即重置。角色速度按原生 60 Hz 单位转换，其他实体按 30 Hz 单位转换。停止、反向与真实碰撞仍以随后到达的权威状态纠正。客机原生镜头在预测位置确定后更新，避免镜头交替追踪权威位置和显示位置。

这次响应优化没有预测新泪弹、命中或道具效果；射击姿态与战斗结果仍来自房主。原生后端公开已有输入采样使用的帧编号用于跨入口去重，并补充受限的客机房间水流写入；水花生命周期复用既有更新拦截，不新增 Hook 或对象所有权。具体布局、校验和验收见[响应优化记录](https://github.com/BMingSY/isaac-lan/blob/main/docs/history/client-response-validation.md#举袋与流水场景补测)。桥接指纹仍要求双方使用同一构建。

## 传输、压缩与积压

套接字由主线程非阻塞轮询。IPv4 地址直接连接；域名在独立线程解析为 IPv4 地址，取消、退出或重新连接不等待 DNS，也不复用旧任务的结果。解析和连接有超时，并依次尝试返回的地址；重连保留原始域名。

消息使用两字节长度前缀，正文整数采用大端编码。当前协议版本为 29；Lua 视图 schema 版本为 17。顶层第 20 项包含药丸颜色效果与鉴定状态，角色库存第 11 项包含原版四个口袋槽的 ID／类型顺序；角色元组第 8 项为 `{材料与原生预览, 正在举袋}`，举袋标记来自主机 `GetItemState()`；举起动画切换前也保持本地移动预测。材料与预览仍使用原有 12 字节，同房和分房都携带。药丸和合成袋状态在库存恢复之后应用，避免库存 setter 覆盖；回退可同时撤销鉴定或恢复材料。顶层字段顺序见 [`sync/world_schema.lua`](https://github.com/BMingSY/isaac-lan/blob/main/src/bridge/sync/world_schema.lua)；扩展指纹随构建变化，所有玩家仍须使用同一扩展构建。协议 28 在运行规则描述符和大厅规则代次之外，为握手／大厅增加每个玩家本地存档允许的新局角色、已解锁角色与规则 ID／版本列表。选角、新局、续玩与重连逐席位校验；新局消耗型资格不重复限制已有角色恢复。可靠结束事件另带显式规则完成标记，与同编号原版结局区分；挑战不改动视图 schema，材料仍完整同步，可见性由本机表现控制。

协议 27 延续协议 26 的压缩载荷使用可移植 DEFLATE（模式 2），无收益时发送原始字节（模式 0）。压缩和解压不调用 Windows Compression API，支持 Windows 与 Proton 混合组队。输出长度、校验和、截断与尾随字节均检查；实时载荷仍限制为 2 MiB。模式 1 的原生 XPRESS_HUFF 读取只保留用于既有 Windows 诊断归档，新发送端不使用它。

| 限制 | 当前值 |
| --- | --- |
| 玩家数 | 最多 4 人 |
| 单消息正文 | 4096 字节 |
| 实时视图原始大小 | 2 MiB |
| 检查点／存档 blob | 8 MiB |
| 大块数据的每段载荷 | 最多 3000 字节 |
| 每个客机的未确认视图窗口 | 4–16 份，按最低已测 RTT 调整 |
| 开始新视图的未确认载荷阈值 | 64 KiB，可再容纳一份正在发送的视图 |
| 每个连接的完整视图历史缓存 | 16 MiB；客机另限 32 份 |

[`core/snapshot_delta.h`](https://github.com/BMingSY/isaac-lan/blob/main/src/core/snapshot_delta.h) 对不透明字节计算无损增量，不识别房间、Boss 或状态字段。复制操作只引用不可变基线，插入／删除不改变引用坐标；长度、范围及基线／结果校验保证还原后的字节与原完整视图一致。接收端还原完整视图后，仍由原 Lua 解码和应用路径处理，没有改变世界视图字段或数值精度。

[`net/compression.cpp`](https://github.com/BMingSY/isaac-lan/blob/main/src/net/compression.cpp) 分别以 DEFLATE 压缩完整视图和相对基线的增量，选择最终载荷较小者；无基线或增量无收益时发送完整视图。头部记录压缩模式与原始长度，世界首块另带楼层代次、完整／增量模式与基线 tick。

每个客机分别保留正在发送的视图和待发送的最新视图。普通发布只替换待发送视图，已经开始分块的视图要完成。换层事务可以终止未发完的旧视图，已入 TCP 队列的旧块仍先到达，接收端在事务起点清理旧的组装状态。

增量基线必须是该客机明确确认已应用的状态；每个增量直接引用它，不依赖被合并丢弃的中间视图。发送窗口同时受未确认视图数量、载荷和缓存容量限制，达到阈值时继续替换待发视图，不阻塞房主模拟或其他客机。窗口依据最低已测 RTT，避免排队抬高 ping 后继续扩大积压。客机显示轨迹跨快照保持连续，外推仍最多 100 毫秒。

新连接从完整视图建立基线；换层、回退等可靠楼层事务清理两端历史，旧代次确认不能建立新基线。当前原生重开标记为受限种类，旧协议不能混连。历史方案与原验收条件见[带宽优化记录](https://github.com/BMingSY/isaac-lan/blob/main/docs/history/world-state-bandwidth-plan.md)。

## 校验边界

| 检查 | 用途 |
| --- | --- |
| 协议版本与联机扩展指纹 | 避免不同协议或引擎桥接代码互相解释数据 |
| 消息长度、字段范围、序号和块偏移 | 拒绝格式错误、重复输入和错误拼接 |
| 检查点、存档、回退载荷的哈希 | 检查传输或文件完整性，不比较两端玩法随机序列 |
| 角色控制器、楼层准备条件、实体 schema | 确认当前原生对象可以应用收到的状态 |
| Mod 指纹 | 提示差异，不阻止开始或加入 |

客机状态应用异常仍会结束其当前游戏并返回局域网大厅。减少这类错误应修正缺失字段、对象生命周期或事务顺序；不能把所有格式与对象检查一起关闭。房主侧异常的范围见[会话与状态恢复](https://github.com/BMingSY/isaac-lan/blob/main/docs/session-lifecycle.md#失败边界)。

## Ping 与卡顿定位

房主通过 `ping/pong` 测量到每个客机的往返时间，并把结果分发给全队显示。它包含轮询和排队耗时，不等于单向网络耗时，也不包含全部玩法响应延迟。

两端日志随原版游戏日志归档。在扩展配置文件 `config.ini` 开启 `[diagnostics] performance = true` 并重启后，每局产生性能窗口；需要载荷明细时另设 `[logging] level = DEBUG`。日志分类、指标口径与汇总命令见[诊断参考](https://github.com/BMingSY/isaac-lan/blob/main/docs/diagnostics-and-resource-testing.md)。

结合两端同一局的日志与性能窗口判断：

- Ping 高、移动预测流畅但效果迟到：先看链路和 TCP 排队。
- Ping 不高、游戏更新变慢：检查房主多房间模拟和状态采集成本。
- 本机回拉、镜头抖动或画面错误：检查预测、对象应用与视图上下文。

日志采样不能单独证明根因。客机卡顿仍由[性能问题 #28](https://github.com/BMingSY/isaac-lan/issues/28) 跟踪；增加诊断和资源回归不表示卡顿已修复，跨层内存变化也不能单独证明泄漏。默认无需录制画面，显示问题再按需补充。
