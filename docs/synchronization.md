# 网络与状态同步

房主运行权威玩法，客机提交输入并恢复房主发布的状态。网络层只处理消息和字节，不识别道具、Boss 或游戏对象；状态采集与应用由桥接同步层负责。

## 数据流与职责

```mermaid
flowchart LR
    I[客机输入] --> H[房主模拟]
    H --> C[采集完整视图]
    C --> L[同步层拆分实时与低频字段]
    L --> E[C++ 二进制编码]
    E --> D[Zstd 完整或参考快照压缩]
    D --> T[UDP 实时通道与可靠恢复]
    T --> R[还原完整字节]
    R --> A[C++ 解码与 Lua 副本应用]
    A --> P[客机本机显示]
    A -->|已应用回执| D
```

| 数据 | 方向 | 交付语义 |
| --- | --- | --- |
| 输入与请求 | 客机 → 房主 | 持有值取最新值，按下边沿保留到消费；请求由房主验证身份与权限 |
| 实时视图 `WorldState` | 房主 → 对应客机 | 每份可还原为完整状态；实时视图允许丢失，丢失不阻塞更新的视图 |
| 可靠事务 | 双向，以房主发布为主 | 大厅、开局、重开、检查点、换层、回退、结束和返回大厅按序交付，不参与视图合并 |
| 聊天通信 `communication` | 客机请求 → 房主；房主 → 接收者 | 独立限额的可靠字节消息，不随世界快照合并；内容契约见[聊天与控制台](https://github.com/BMingSY/isaac-lan/blob/main/docs/chat-console.md) |

生命周期消息 `lifecycle` 使用独立限额的可靠通道，发送者由连接确定；载荷首字节区分重开（1）与动画跳过（2），由桥接分发给各自消费者。动画同意绑定运行标识、楼层代次、动画类型和序号，名单及结果只由房主发布；运行层校验投票所属的运行标识、代次和在线名单。全员同意后的 `restart` 消息携带新运行标识、世界代次和开局设置，`ready` 同时校验运行标识与首 tick。投票及退出／重建顺序见[全队重新开局](https://github.com/BMingSY/isaac-lan/blob/main/docs/session-lifecycle.md#全队重新开局)。

通关后的 `returnLobby` 回执携带当前运行标识。已退出的一端进入 `returning`，继续轮询连接而不启动游戏；房主收齐当前在线成员的回执后清理本局数据、提升大厅规则代次并发布 `lobby`。旧局回执与旧规则下的准备请求不能解除新大厅的屏障，结局播放速度不要求一致。

第三方动作使用有独立限额的可靠消息，具体契约见 [Mod API](https://github.com/BMingSY/isaac-lan/blob/main/docs/third-party-mod-integration.md)。房主内部的 `Frame` 仅汇总输入，不用于让客机重放同一套玩法模拟。

## 输入与时间

客机按本机渲染帧采样输入，同一帧的重复轮询只采一次。`input_hz` 支持 30／60，默认 60；每份输入包含 16 个量化动作值、按下边沿和本机鼠标目标。卡顿后只发送当前采样，不补发积压的历史样本。

单人输入固定 43 字节：16 个大端 `uint16` 动作值、一个 `uint16` 边沿位图、一个 `uint8` 鼠标按住标记，以及两个大端 IEEE 754 `float32` 房间目标坐标。标记仅允许 0／1；坐标必须有限且绝对值不超过 32768，未按住时两轴必须为零。鼠标目标跟随输入序号和房间／楼层上下文，暂停与同层转场保留按住状态，换层、断线超时及会话清理释放。聊天和菜单捕获输入后，鼠标须先松开才能重新射击；托管期间由托管输入接管瞄准。

房主在原生模拟步骤前消费输入，完整更新正常为 30 Hz；运行中不等待每名客机逐帧提交。持有值可以复用，边沿消费后清除；超过 500 ms 没有新输入时使用中性输入。首次加载屏障见[会话生命周期](https://github.com/BMingSY/isaac-lan/blob/main/docs/session-lifecycle.md#大厅与开局)。

客机完成加载并发送 `ready` 时，房主同时清空该席位的持有输入、边沿、房间上下文和确认序号。重连后的输入序号从零开始；第一份实时视图即使早于新输入到达，也不能携带上次连接的确认序号。

| 标识 | 用途 |
| --- | --- |
| `tick` | 权威状态的模拟序号，用于排序与应用回执 |
| `inputSequences` | 房主已消费的各玩家输入序号，用于预测确认 |
| `floorEpoch` | 换层、重建和回退的代次，用于隔离不同世界状态 |
| 房间键 | `(dimension, roomIndex)`，与楼层代次共同限制输入的适用范围 |

回执确认的是状态应用完成，不比较双方的 RNG。菜单和本机界面消费本机物理输入；暂停、退出等会话操作走可靠命令。移动预测的显示边界见[房间与表现](https://github.com/BMingSY/isaac-lan/blob/main/docs/rooms-and-presentation.md#移动预测与镜头)。

HUD 延迟独立于诊断日志开关。运行层为客机输入序号保留有界的本机采样时间，成功应用视图后测量新确认的输入耗时；重复、倒序和已淘汰的序号不产生样本，首个歧义序号 0 不计入。`syncLatency` 上报携带运行标识、世界代次和 `{毫秒值 u16, 样本年龄毫秒 u16}`，发送者取自连接；房主只接受当前局、当前代次且已就绪的在线席位。`latency` 广播携带同样的运行标识与代次，随后按四个槽位依次编码网络和同步样本，`65535` 表示未知。两种报告的间隔为 500 ms，样本年龄在每次转发时保留，网络传输时间不作为新的测量加入同步值。状态接口的 `network0..3`、`sync0..3` 返回未过期的显示值，未知为 `-1`；原有 `ping0..3` 继续保留最近 RTT 供预测使用，不受 HUD 过期策略影响。显示口径见[房间与表现](https://github.com/BMingSY/isaac-lan/blob/main/docs/rooms-and-presentation.md)。

## 完整视图与实体身份

每份视图包含全队主要角色状态、共同楼层与地图，以及接收者当前房间的实体、网格和表现。同房角色携带完整外观，异房角色保留多人 HUD 所需状态。角色的 `ControlsEnabled` 与 `ControlsCooldown` 同属权威状态；客机不推进原生角色更新，控制冷却的递减和归零必须随快照恢复。玩家字段同时携带 `Friction`，供本机重放蜘蛛网、地面减速后的移动。库存字段 12 `subplayer` 为 `false` 或 `{type, hearts}`；骸骨兼容组件先恢复原生形态配对，再分别恢复当前与隐藏形态生命，不重建隐藏身体的道具库存。库存字段 14 `order` 为 `false` 或里以撒的 16 个大端 `i32` 有序道具 ID 组成的 64 字节串；完成道具数量恢复后再恢复顺序，重复快照不推进选择。任意 Mod 私有表、Lua 源码和原生指针不进入视图。

采集以 `(floorEpoch, tick)` 为不可变代次，在该代次内复用公共字段、角色和同房采集结果；下一 tick 仍读取当前原生状态，逐项比较未变化的库存列表和地图记录可复用不可变值及编码片段。角色持有物与矿车关联在角色所属房间内采集，房间内部索引只用于转换为稳定实体 ID。分层投影复制角色与房间容器，编码缓存复用其不变的子表。跨客机的角色、实体与网格片段只在多个接收者时建立：多个客机共享角色字段，同房且同维度的客机还共享实体与网格编码。音效和演出按接收者筛选。字段由 [world_schema.lua](https://github.com/BMingSY/isaac-lan/blob/main/src/bridge/sync/world_schema.lua)、[fields.lua](https://github.com/BMingSY/isaac-lan/blob/main/src/bridge/sync/fields.lua) 和 [entity_schema.lua](https://github.com/BMingSY/isaac-lan/blob/main/src/bridge/sync/entity_schema.lua) 定义。泪弹、跟班、效果与精灵的常用属性通过[具名批量能力](https://github.com/BMingSY/isaac-lan/blob/main/docs/native-backend.md#实体字段批量读写)读写，Lua 模板决定字段顺序，版本后端保留原属性语义；其他类型使用游戏 Lua API。

[分层投影](https://github.com/BMingSY/isaac-lan/blob/main/src/bridge/sync/layers.lua)把道具列表、饰品、地图、进度、诅咒、交易、药丸、生成道具定义、房间布局／轨道／夹层信息编码为低频依赖；充能、血量、消耗品、便便／合成袋／临时效果、位置、实体、网格、动画及一次性表现留在实时部分。需要发布时仍读取当前 tick 的权威状态，低频指依赖传输按变化发送，不使用旧采样代替当前字段。UDP 依赖使用递增修订号和可靠有序交付，比较独立编码与引用上一份可靠依赖的 prefix 编码，只发送较小者；首份依赖只执行独立压缩；一次最多有一份未确认的可靠副本，其间的新变化合并为最新候选，允许跳过中间修订。初始视图可靠交付；建立应用确认基线后，尚未被应用确认的新修订同时内嵌于实时视图，避免可靠副本丢包阻塞整帧。内嵌副本可先于可靠副本到达，接收缓存按修订号合并，可靠压缩字典独立维护。实时视图明确引用修订号，客机仅在对应数据齐全时还原完整视图，不能套用最新库存或跨房间拼接。依赖缓存、未完成视图和修订号在代次屏障清理。

世界 schema 为 41，字段 `captured` 是主机开始本轮采集的单调时钟毫秒数；离线生成的无时钟状态使用 0。采集回调返回实时字节和可选依赖字节，应用回调的第五个参数接收对应依赖。完整状态的诊断采集仍由 `state.capture` 提供；生产传输使用 `state.captureTransfer`。

库存的 `activeData`（字段 13）保存四个主动槽的内部状态：每槽为大端 `{id:i32, data:i32}`，前 32 字节；末尾一个字节表示打包盒是否有内容（0／1），合计 33 字节。空槽的状态为 0。打包盒标志只驱动客机图标，内容与收放仍由主机原生对象管理。副本先恢复各槽道具身份，再恢复状态，最后设置充能，确保依赖内部状态的容量与图标一致。应用前完整校验槽位身份与道具状态；重复状态不刷新图标缓存，也不重放道具使用。联机幽灵的隐藏背包继续由原生转换负责。

角色的 `temporaryEffects`（字段 9）是按类别和编号排序的实际效果集合，每项为 `{kind, id, count}`：类别 1／2／3 分别为道具、饰品和 Null 效果。编号保留有符号 32 位值，层数为 1～65535，最多 4096 项，同类编号不得重复。副本先校验整组，再复制本机效果身份，按差值增减并清除权威集合中已不存在的效果；原生列表引用不跨越增删操作。这个集合供原生外观和状态查询使用，不调用 UseActiveItem／UsePill，也不在客机推进效果计时或结算玩法。

角色 `pose` 的武器前缀由 [weapon_pose.lua](https://github.com/BMingSY/isaac-lan/blob/main/src/bridge/sync/weapon_pose.lua)读取：大端 `BBI4I4f` 头之后为五个武器槽，各槽以一字节存在标记开始；存在时依次为 `I4ffffI4`（类型、冷却、最大冷却、蓄力、原生蓄力上限、武器修正标志）。其后的装扮与层状态保持不透明。攻击显示可以构造只替换蓄力的本地副本，不能覆盖冷却、类型、权威快照或后续载荷；此副本不参与状态编码和发送。

实体字段 28 `tether` 为 `false` 或 `{points, sprite, ownerId, ownerPosition, familiarPosition}`；点载荷为大端 `u16` 数量及每点三个 `f32` 坐标。其几何与精灵来自权威跟班，客机仅绘制，并按本机身体与跟班显示位置平移端点。

NPC 字段 `npc` 是 25 字节记录：六个大端 float32 依次保存 `V1`、`V2` 和 `TargetPosition` 的 X／Y，末字节为 `IsBoss()` 的 0／1 分类。前两个暂存向量保留原生整数哨兵的浮点位模式；目标坐标必须有限，接收端在修改实体前检查整条记录。客机渲染和原生 Boss 血条使用同步的目标点与分类，不依赖被暂停的 NPC AI 来补齐状态。

实体 ID 由房主原生身份表统一分配，状态采集和伤害事件共用同一身份；借用地址、InitSeed 与实体索引只用于识别原生对象是否替换，不在线上传输。客机维护 `ID → EntityPtr`。同一活动对象复用其 `EntityPtr` 与显示轨迹记录，原生引用失效或角色对象替换时重新建立引用；换房清理显示轨迹，退出清理全部引用。恢复时先回收过期实体，再创建／更新实体，最后绑定父、子、生成者、目标和角色持有引用。`held`（实体字段 27）是被抱起对象的稳定 ID，无对象或不在当前视图时为 `0`；异房角色同样清空旧链接。身份与本机地址、实体池槽位无关；原生对象仍由游戏分配和释放。特殊实体引用通过兼容组件和具名后端能力接入，见[原生能力参考](https://github.com/BMingSY/isaac-lan/blob/main/docs/native-backend.md#实体引用与房间数据)。

实体的兼容显示字段由 `compat/visuals` 按实体类型分派给对应适配；包含额外 Sprite 的组件复用实体编解码器的采集／恢复接口，保留原生缓存外观的所有权和生命周期。

客机应用完整视图时遵循[恢复顺序](https://github.com/BMingSY/isaac-lan/blob/main/docs/layers-and-compatibility.md#采集与副本恢复)，全部成功后才提交 tick。原生楼层未准备好时保留最新视图，延后应用。普通状态允许在原生半帧边界应用；首次视图、暂停／名单变化、换层、换房及角色替换在完整更新边界处理。`betweenUpdates` 预检不写入房间或角色，返回 `false` 表示继续等待。

客机保留显示和资源清理所需的原生更新，拦截同步实体的玩法更新与碰撞。伤害、拾取、房门决策和道具效果由房主执行；副本恢复不重放使用动作。恢复及客机原生更新期间暂时关闭进度写入，避免库存重建利用本机收藏历史重新触发成就；主机发布的进度仍可显式应用。进度载荷包含 642 个成就字节、523 个 32 位计数，以及同样索引的 642 个奖励成就字节与 523 个奖励位掩码字节；后两者只记录本局实际获得的奖励，随实时视图、检查点和可靠结束事件恢复。成就字节只允许 0／1，奖励位掩码单项为一个字节；计数的原生语义由后端解释，网络层只编码值。个人合并及退出提交见[会话恢复](https://github.com/BMingSY/isaac-lan/blob/main/docs/session-lifecycle.md#暂停与退出)。

## 战斗表现事件

顶层 `combat` 是按接收者过滤的有界事件记录，随完整实时视图重复携带。记录由主机在原生 NPC 伤害判定返回后产生，包含递增序号、tick、楼层代次、房间、来源与目标实体 ID、接受结果和原生闪烁时长；接受结果包含 Mod 回调的否决，不表示已经扣除血量。血量、死亡和实体生命周期仍由权威状态决定。记录保留最多 90 tick、512 项，传输缺包由后续视图覆盖；长时间断流可以丢失纯表现，不影响玩法恢复。

实体字段 `combat`（29）表示当前可预测接触的事实：0 为不参与，1 为可受击、允许闪烁且不带 `FLAG_FRIENDLY` 的 NPC，2 为已经离开发射等待、无特殊 TearFlags 的普通蓝／血泪。主机读取实际弹体属性，不能用玩家属性替代；副本碰撞已关闭，不能从副本碰撞类反推主机资格。预测仍按本机发射者筛选。

客机在原生恢复之前验证事件长度、数量、序号、枚举和时长。表现组件按楼层／房间过滤，按事件序号去重，再用来源／目标实体身份匹配预测。旧状态或不同扩展指纹不能接入。表现时钟及取消规则见[房间与表现](https://github.com/BMingSY/isaac-lan/blob/main/docs/rooms-and-presentation.md#命中表现预测)。

## 传输、压缩与积压

连接使用 IPv4／IPv6 UDP，静态链接带有 [Windows 双栈适配](https://github.com/BMingSY/isaac-lan/blob/main/vendor/enet/README.isaac-lan.md)的 ENet 1.3.18。主机在同一端口接受两种地址族；系统不支持 IPv6 时回退到 IPv4 监听。客机按目标地址族建立套接字。域名在独立线程查询 A／AAAA 记录，候选地址去重后优先 IPv6、交替尝试两种地址族；连接失败或单地址等待耗尽后尝试下一候选，解析和连接共用 10 秒总期限。取消或重连使旧解析结果失效。

菜单地址与端口分开输入；地址可为域名、IPv4 或 IPv6，IPv6 可带方括号，链路本地地址的 `%接口编号` 按连接发起端的接口编号解释。[命令端点](https://github.com/BMingSY/isaac-lan/blob/main/src/bridge/core/endpoint.lua)用 `[IPv6]:端口` 消除冒号歧义。地址族、128 位地址和接口编号只用于本地套接字与来源校验，不改变协议报文。DNS 解析不提供中继或 NAT 穿透，所选地址仍需可达且允许对应 UDP 端口。

每个会话的 [网络线程](https://github.com/BMingSY/isaac-lan/blob/main/src/net/udp_io.cpp)通过 socket 事件和唤醒事件处理连接、收发、消息封装、分块组装及实时视图压缩／解压。主线程的 `Session::poll` 只消费已交接的结果、推进协议状态；主机取得输入后仍在当前更新中推进游戏，不经过后台任务往返。聊天与心跳的字节收发不等待下一帧，聊天的业务分发和界面更新仍由主线程执行。

主线程通过有界单生产者／单消费者队列交换拥有独立存储的可靠消息；发送视图以及接收的视图、持有输入和累计应用回执分别使用单值邮箱替换旧值。接收邮箱记录此前可靠消息的交接序号，只有这些消息已消费后才能交付实时值；换层、重开和退出边界使旧实时值失效。可靠接收容量耗尽时只关闭对应连接，网络线程继续服务同一监听端点的其他玩家。网络工作线程不调用 Lua、游戏 API、日志回调或诊断回调；诊断样本有界交接后由主线程记录。存档和回退使用独立的 [大数据工作线程](https://github.com/BMingSY/isaac-lan/blob/main/src/net/byte_worker.cpp)，在后台压缩、解压并校验完整性，避免占住网络线程。原生存档采集、Continue 和副本应用必须在主线程执行。取消任务后，已开始的任务只完成其独立字节结果；旧会话退出等待在线程退休阶段完成，不阻塞下一次重连的启动。

游戏协议版本为 53。ENet 建连标记固定为 `ILAN`，不使用游戏协议号提前拒绝连接。双方先在可靠通道交换独立、未压缩的[兼容性报文](https://github.com/BMingSY/isaac-lan/blob/main/src/net/compatibility.h)，其信封、修订号和字段顺序独立于游戏协议。报文携带 Isaac LAN 版本号、扩展指纹和游戏协议号，三项必须完全一致；版本号来自 [VERSION](https://github.com/BMingSY/isaac-lan/blob/main/VERSION) 的编译值，扩展指纹包含目标游戏版本标识和 DLL 文件内容。预检通过前不解压或解析游戏消息，不接纳大厅席位，也不启动归队恢复。初次加入和重连共用这一检查。

UDP 游戏消息使用消息封套和连接代次，按完整报文交接，不使用字节流长度前缀。[统一消息封装](https://github.com/BMingSY/isaac-lan/blob/main/src/net/wire_codec.h) 对至少 256 字节的控制、聊天及扩展消息尝试压缩，仅在包含封套后仍更小时使用 `0x80 + 压缩封套`；小消息和不可压缩消息保持原正文。实时视图、检查点和回退载荷先整体压缩再分块，不逐块重复压缩。

[Zstd 适配器](https://github.com/BMingSY/isaac-lan/blob/main/src/core/zstd.cpp) 使用快速级别 `-1`。实时视图优先引用已确认不可变快照的 prefix 帧，并按下述策略抽样比较独立帧；检查点及回退使用独立帧。无压缩收益时使用原始字节。prefix 直接引用完整快照，不训练字典或另外构造字节补丁。压缩上下文由所属工作线程持有并复用，每次调用结束清除借用的 prefix；不同客机之间不共享基线。实时视图首块标明完整／参考模式、基线 tick 与楼层代次。

压缩封套为一字节模式和四字节大端原始长度：`0` 为原始字节，`3` 为独立 Zstd 帧，`4` 为 prefix 帧；`1`／`2` 仅保留旧 XPRESS／DEFLATE 读取。Zstd 帧必须含已知原始长度和内容校验和，不接受训练字典 ID、串接帧或尾随字节。解码前按通道检查输出大小和窗口：消息 4096 字节、实时视图 2 MiB、存档及回退 8 MiB。Zstd 静态链接，不依赖系统安装或额外 DLL。

该增量位于完整状态编码之后，客机也要还原完整字节再解码。它减少传输量，不免除整份状态的采集、编码与解码成本。已编码视图通过所有权移动交接；接收解压直接借用当前报文的压缩载荷，借用不跨越报文生命周期。网络层不按游戏字段解释或修改状态。

UDP 使用四个通道：可靠控制、依赖与一次性按键；非可靠持有输入；非可靠实时视图；可靠完整视图恢复。ENet 负责连接、校验和及可靠重传，MTU 为 1200 字节。能放进一个报文的实时视图直接非可靠发送；超出 ENet 单包预算且分片数不超过 1024 时使用[独立分片](https://github.com/BMingSY/isaac-lan/blob/main/src/net/world_shards.h)，单包预算扣除 ENet 头、校验和与代次封套。每组最多 8 个 1024 字节数据片；整份视图不超过 3 个数据片时只增加 1 个 GF(256) 校验片，恢复任意一个缺片，较大视图默认每组增加 2 个校验片，恢复任意两个缺片。[冗余策略](https://github.com/BMingSY/isaac-lan/blob/main/src/net/world_redundancy.h)在至少 3 秒、90 份连续完好视图后降为每组 1 片；接收端每 500 ms 上报当前代次的完成、修复及丢弃计数。出现修复、丢弃、回执积压或质量反馈超过 2 秒未更新时恢复 2 片。反馈乱序不能抹去已观察的损失，换层重新积累证据。小增量也使用同一路径，避免有序分片因新视图到达而丢弃旧视图的迟到片。分片携带视图 ID、总长度、组号和片号，无序交付、重复去除，整份恢复后才解压。超过纠错能力时等待更新视图；部分视图受数量和字节上限约束，不要求补完旧帧。单片末组只增加一个校验片。满组校验数据增加约 12.5%／25% 载荷，数据片填满时，两片／三片的小视图分别增加约 50%／33% 校验载荷，另计分片头。不提供持续丢包或带宽不足时的交付保证。

发送端保留完整视图窗口，关闭 ENet 对单个无序包的随机丢弃；每连接的[字节预算](https://github.com/BMingSY/isaac-lan/blob/main/src/net/world_pacing.h)平滑移交实时报文，每轮服务最多 16 个片。预算计入数据片、校验片及协议头估计，空闲时只积累有界突发额度。路径拥塞依据 ENet 在网络线程测得的 RTT：相对最近两秒的最低值持续增加超过 25 ms，且至少三份回执跨越 100 ms 时降低速率；孤立抖动不降速，健康回执逐步恢复。主线程应用等待只限制未确认窗口，不作为路径拥塞；最低值会随旧样本过期，允许稳定的线路延迟变化后恢复速率。尚未发完的视图超过 250 ms、仍剩一半以上载荷且预计还需超过 100 ms 时，可放弃剩余分片并改发最新视图；被选中的替代视图必须发完，避免持续替换导致始终无法组装。已移交 ENet 的可靠恢复不会被取消。输入与控制消息不等待实时额度。可靠完整恢复预占路径预算，极大 ENet 分片同样计费；重传仍由 ENet 管理。回执超过两倍最低 RTT 且至少 200 ms 未推进时，新视图发送间隔至少 100 ms。可靠恢复同一时刻最多排队一份完整实时视图，间隔至少 500 ms；依赖仍必须匹配修订号，过期恢复结果不覆盖新状态。尚无应用确认基线时只推进这份恢复。已有基线时，实时视图使用独立的有界回执窗口，不等待旧恢复包的可靠重传结束；可靠恢复仍只保留一份。可靠事务末块移交 ENet 后，等待未确认尾部低于一个分块再发送新视图。各通道共享链路容量与可靠发送窗口，恢复流量与实时流量的容量需分别计算，不能把丢失记录退休当作 ENet 已释放恢复包。

每个客机独立持有待发送的最新视图和已确认基线。每份 prefix 帧直接引用该客机已确认应用的基线，不依赖丢失的中间视图。确认推进压缩基线，并释放有界发送窗口；窗口按最近两秒的最低已测 RTT 设置，为丢失替补保留 8–16 份状态，同时限制未确认字节和缓存容量。UDP 对超过 500 ms 的未确认记录按丢失处理，释放空间以发送最新视图，不无限等待特定丢包的回执；可靠恢复的候选基线单独保留。缺失基线时丢弃当前增量，确认停滞时以完整视图恢复；持续收到应用确认时不强制周期性完整帧，通常先压缩 prefix；每 30 份视图比较一次独立完整编码，初始化、恢复完整帧或 prefix 大于等于原始字节的 75% 时立即比较，取较小结果。未抽样帧不额外压缩完整候选，也不记录虚构的完整压缩对照量。不把正常丢包当作协议损坏。

应用回执走非可靠实时通道，使用无序报文，与持有输入的 ENet 顺序相互独立；只保留最新累计确认，每 100 ms 重复最新值，接收端按代次和已确认视图编号拒绝旧回执。这样较新的输入不会淘汰迟到的回执，回执也不会淘汰持有输入；代次屏障清除旧回执。大视图的无序片在 ENet 的同一个 1024 序号窗口内发送，必要时跳过窗口尾部；超过该窗口容量的极大载荷使用 ENet 分片和可靠恢复。

UDP 持有输入发送最新方向与输入序号，并重复携带最近 12 个样本内的最多 4 份一次性按键事件。事件同时通过 `inputEdges` 可靠通道兜底，两路使用独立、连续的事件序号。[事件队列](https://github.com/BMingSY/isaac-lan/blob/main/src/net/input_events.h)去重并等待缺失的前序事件，持有输入推进到对应样本后逐个在主机更新中消费，不能因重传或集中到达而重复、合并或倒序执行。重复历史与接收队列均有界。事件与原房间／楼层上下文绑定；超过 120 个输入样本、或最近持有输入超过 500 ms 未更新时失效。失效事件仍推进事件序号，避免阻塞后续正常输入；新局和重连重新初始化序号。

主机的可靠代次屏障使旧视图失效。可靠按键允许补齐跨屏障的事件序号，消费前按原楼层和房间过期处理；运行层还以主机实际位置校验输入上下文，旧楼层动作不能应用到新楼层。实时通道抢先到达的下一代状态会被丢弃，待控制事务到达后由后续完整视图恢复；房间目的地和楼层推进仍由会话层决定。

| 限制 | 当前值 |
| --- | --- |
| 玩家数 | 最多 4 人 |
| 单消息正文／每段大块载荷 | 4096／3000 字节 |
| 完整实时视图／检查点与存档 | 2／8 MiB |
| 未确认视图记录 | 每客机 8–16 份，另保留一份可靠恢复候选 |

| 完整视图历史缓存 | 每连接 16 MiB；客机另限 32 份 |
| 主线程与网络线程的消息交接 | 每方向每连接 128 条可靠消息；接收视图、持有输入和累计回执各保留最新值；已完成可靠载荷达到 4 MiB 后拒绝新增大数据，可额外容纳当前一份存档，普通消息仍受 128 条上限约束 |

网络线程将可采集状态反馈给游戏线程；存在待发视图、加载事务、未完成恢复或已满的发送窗口时，跳过对应客机的采集与编码。陈旧分片符合替换条件时允许采集一份新视图，被选中的替代视图必须发完。未采集期间不提前清空该客机的事件队列，重新开放后采集当前状态。达到发送窗口上限时保留有界的待发视图；UDP 窗口也可由超时释放，不要求每份视图都得到确认。任一客机的积压不要求主机暂停其他玩家。换层／回退事务使旧视图、组装状态和基线失效；新连接从完整视图建立基线，旧代次回执不能建立新基线。

## 状态编解码

Lua 决定游戏字段契约、采集与恢复顺序，通过游戏 API 或具名批量能力访问属性。[`state_encode(value, memo)`／`state_decode(bytes)`](https://github.com/BMingSY/isaac-lan/blob/main/src/engine/state_codec.cpp) 在主线程通过共用 Lua 5.3 ABI 批量处理数组，字节读写与大小限制位于可移植的 [state_codec.h](https://github.com/BMingSY/isaac-lan/blob/main/src/core/state_codec.h)。编解码接口不访问游戏对象、原生布局或网络连接。Lua [参考实现](https://github.com/BMingSY/isaac-lan/blob/main/src/bridge/sync/codec.lua) 用于离线对照与未绑定原生能力的夹具。

值仅包含布尔、整数、有限 float32、字符串和普通数组。类型标记、整数宽度和大端格式由原生与 Lua 参考实现的逐字节对照检查；整数与浮点数的类型、负零及有符号 64 位值保持原样。编码使用连续缓冲区，Lua 分配失败时由 userdata 的终结器释放 C++ 缓冲区；正常返回或 C++ 校验失败立即释放。

`memo` 由采集组件持有，只标记不可变的数组。库存、地图、实体与网格字段每次仍实时读取；完全相同的道具列表、地图记录和网格列表可复用上一采集 tick 的值及编码片段，变化时新建数组。房间采集只保留上一代已观察房间的网格列表，用于复用未变化的网格及其精灵记录；按维度与房间索引隔离，未继续观察的房间在下一代淘汰，tick 回退、楼层及会话重置清除历史。原生采集使用组件独占、最多 256 项的只读数值数组池，共享位模式相同的向量和颜色，容量满后继续独立采集，会话重置清空；池中只有普通值，可跨房间复用。原生对象不进入这些缓存。编码缓存记录完整字节、节点数与相对深度，重复引用仍计入整份视图的预算；普通数组不自动缓存，不可在标记后修改内容或缓存元数据。

客机的 `state_decode_view(bytes)` 可在单次解码内共享完全相同、最多 16 项的数字／布尔叶数组，缓存最多 4096 项，短整数数组不入缓存；此路径的叶数组只读，容器及不同解码之间不共享身份。普通 `state_decode` 保留独立数组语义，两者字节、类型、节点／深度限制和失败清理一致。客机仅在预检尚未进入原生恢复时保留最新解码结果，用于半帧延后到完整更新的同一份状态。字节或 tick 变化、楼层等待、视图重置及开始恢复都会使该缓存失效。库存比较直接检查角色类型、道具种类／数量和饰品槽，仍保留每 30 tick 的原生库存纠偏。同次采集或恢复中的角色共享道具 ID 与被动分类目录，只保存普通值，不保留原生配置对象；下一次操作重新枚举目录。数量查询方法只在当前角色操作内绑定，所有持有量仍实时读取，不以道具总数判断库存是否变化。

泪弹、跟班、掉落物和效果实体的 `nativeFields`（实体字段 26）携带数值块，顺序为通用属性数组、类型属性数组、精灵偏移、精灵缩放和颜色；原位置 8、9、15、16、17 为 `false`。数值块沿用相同的标记和大端编码，由具名字段计划在原生端直接采集和恢复，避免逐帧构造、遍历中间 Lua 表。其他实体及离线 Lua 参考路径仍使用展开的属性数组，字段 26 为 `false`。实体字段 18 仅对泪弹携带帧龄，供客机预测识别同次射击；其他实体保留为 `false`，世界时钟仍由顶层帧号恢复。精灵字段 11 同样保留为 `false`，完整颜色（含 colorize）只在原生 Sprite 块中携带和应用一次。字段名称与顺序由 [entity_schema.lua](https://github.com/BMingSY/isaac-lan/blob/main/src/bridge/sync/entity_schema.lua)、[entity_codec.lua](https://github.com/BMingSY/isaac-lan/blob/main/src/bridge/sync/entity_codec.lua) 和 [fields.lua](https://github.com/BMingSY/isaac-lan/blob/main/src/bridge/sync/fields.lua) 定义，原生白名单不决定玩法或引用关系。

通用属性包含 `SortingLayer` 和 `RenderZOffset`，与 `DepthOffset` 一起恢复主机的绘制排序；房间重建及 Boss 阶段变化使用当前快照值，不依赖客机实体的分配次序。

## 校验与失败边界

| 边界 | 检查与结果 |
| --- | --- |
| 握手 | Isaac LAN 完整版本号、扩展指纹和协议号必须一致；第三方 Mod 指纹差异只提示 |
| 消息与分块 | 校验字段范围、序号、偏移和完整性；UDP 丢弃重复、过期或代次不符的实时状态，畸形消息仍拒绝 |
| 状态编码 | 只接受布尔、整数、有限 float32、字符串和数组；少于 250000 个节点，深度小于 12；字符串和数组长度最多 65535 |
| 副本应用 | 校验楼层准备、角色控制器与实体字段；失败不提交完成 tick，已执行的原生写入不会自动回滚 |

协议与字段版本分别由 [protocol.h](https://github.com/BMingSY/isaac-lan/blob/main/src/net/protocol.h) 和 [world_schema.lua](https://github.com/BMingSY/isaac-lan/blob/main/src/bridge/sync/world_schema.lua) 管理。变更字段时同步更新生产者、消费者、版本／指纹和相关契约。

兼容性失败只拒绝对应连接，房主在主线程记录原因与双方版本，其他玩家和原归队席位不受影响。客机状态中的 `compatibilityError` 保留 `reason`（`version`、`fingerprint`、`protocol` 或 `unavailable`）、`localVersion` 和 `remoteVersion`，由菜单显示失败原因及双方版本，下一次连接清除旧错误。同版本不同 DLL 显示构建不一致；对方未提供有效兼容性报文时，其版本为空并显示“未知”，不能据此断言具体版本不符。未支持此报文的旧版不能加入，其自身界面仍使用原有错误提示。

世界字段版本为 36，精灵原生载荷使用格式 2，包含动画挂点帧和事件状态。角色字段 10 保存 `GetBabySkin()` 的身份，伴随角色在库存之前恢复该值。角色和服装在渲染边界仍恢复权威姿态；同名动画通过完整状态恢复，避免每帧重新初始化动画。不同字段版本不能互相应用，嵌入模块与 DLL 指纹继续参与连接校验。

世界字段 `challenge` 为 `false` 或 `[规则编号, 规则版本, 组件载荷]`，挑战组件验证并恢复自身的动态进度；具体契约见[联机挑战](https://github.com/BMingSY/isaac-lan/blob/main/docs/lan-challenges.md)。启用个人地图策略时，地图的显示与已探索字段按接收者投影；布局、清场与掉落仍由同一权威楼层采集。UDP 消息布局通过协议版本校验，世界字段与嵌入模块通过各自版本和扩展指纹校验。

客机协议或应用错误会结束其当前游戏并返回大厅；房主自身的桥接错误可能结束整场会话，详见[失败边界](https://github.com/BMingSY/isaac-lan/blob/main/docs/session-lifecycle.md#失败边界)。Ping 是包含主机消费回包及传输排队的往返时间，不能代替状态处理耗时；测量与排查方法见[诊断参考](https://github.com/BMingSY/isaac-lan/blob/main/docs/diagnostics-and-resource-testing.md)。
