# 分体模型、药丸归属与妈刀回退：2026-10-24

本轮处理 PR #117 手动游玩补充的三项反馈，无独立 feedback 编号。基线为 `293a5e7a86e92ad81fc0a480024baa5f72da6290`，候选为包含本记录的提交；Windows x86 `1.9.7.17.J460`，分体／药丸种子 `LBCD0G4M`、武器回归种子 `YV039KQF`，UDP 每方向 40 ms，无额外抖动或丢包。

妈刀的新相对轨迹估计已按用户要求撤回，恢复 `f0097a5` 的父实体相对位置显示。此前记录的“同快照连续位移”属于已撤回实现，不能继续作为当前行为的验收结论。其余钥匙门、Boss 血条、下降及过门计时修复保留。

## 原因与处理

| 用户反馈 | 核查结果 | 处理 |
| --- | --- | --- |
| “断头台”客机模型多出身体／头部 | 截图和存档中的道具是剪刀（325）；原生分体判定会读取 TemporaryEffects，旧同步只覆盖三个指定道具 | 同步真实的道具、饰品、Null 临时效果集合；按层数差值恢复、清除过期效果，不重放使用动作。剪刀、锯齿剪（107）、断头台（206）和飞头攻击（729）一起检查 |
| 锯齿剪的独立身体不可见 | 跟班绘制使用自身额外组件中的五个缓存 Sprite 和四个图层，普通实体 Sprite 不包含这些数据 | 道具兼容组件复用普通 Sprite 编解码；版本后端只借用和恢复已有原生组件，不运行跟班 AI、不重建所有权，不从当前玩家外观推导旧身体 |
| 客机吃 Speed Down，主机显示白色闪光 | 实际用到效果 13 后复现。Sad 动作和文字已经归客机，原生全屏泛光仍写进主机的 Game 字段；同房、分房均有证据 | 角色更新和嵌套道具／卡牌／药丸动作共享所属玩家的后处理作用域，泛光计时与强度随该玩家演出状态恢复。主机只推进一次，客机不再次执行药丸 |
| 妈刀回收越过角色模型 | 新相对轨迹外推在回收阶段可能越过父角色 | 撤回该估计及专属状态，恢复旧逻辑；保留原版轨迹刷新表现，不继续以提高刷新率为由外推返回刀刃 |

临时效果契约及演出 pose 改变，世界 schema 34、协议 43。实体兼容显示分派移至 `compat/visuals`，Boss 和道具各自维护匹配及额外数据；通用实体编解码只提供 Sprite 采集／应用回调。原生能力限制见[参考](https://github.com/BMingSY/isaac-lan/blob/main/docs/native-backend.md)。

## 保留的原始失败与重启原因

各轮资料均通过逐文件恢复。原始日志、画面、DLL、场景及报告留在私有验收产物中，不提交玩家数据。

| 轮次 | 结论 |
| --- | --- |
| 01 | 仅回退妈刀的基线观察；分体场景残留干扰后续用药，客机未真正吃到指定药丸，不能作为药丸核查完成。两端强制退出，堆观察器 5，无转储 |
| 02 | 基线先检查用药，再检查分体；确实吃到两次效果 13，分别同房和分房，另有主机用药对照。正常退出、堆观察器 0、无转储。画面确认泛光归属错误，本轮是复现证据，不是修复通过 |
| 03 | 泛光隔离和通用临时效果已加入；剪刀模型恢复，另发现锯齿剪独立身体缺少缓存图层。飞头过早收回使固定观察窗口断言失败；两端强制退出、堆观察器 5、无转储。不计整轮通过 |
| 04 | 四个分体场景双端通过，图层及画面核对完成；夹具清理恢复了全局帧入口，覆盖组合调度器，导致后续场景未启动。主动结束，双端退出与堆观察器均为 0，无转储。调度器重新接管入口并补离线回归 |
| 05 | 四个分体场景再次通过，Speed Down 的两次实际用药和归属已核对；新房第一次更新生成的怪物没有被初始清场覆盖，tick 364 的怪物接触伤害打断 Sad 动作，原断言失败。增加目的地加载后的清场，不放宽动作断言。两端被强制退出、堆观察器 5、无转储 |

每次重启仅用于加载新 DLL／夹具，或结束无法继续的失败场景；没有将未启动、未触发或缺少一端结果的场景计为完成。前期离线检查中已删除旧文件但索引未更新造成的语法检查失败、一次使用无构建文件的旧目录的失败也保留，随后正确路径与完整检查均通过。
