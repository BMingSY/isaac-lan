# 2026-10-15 发布前集中验证

基线为 `b019dc5`（包含客机响应、合成袋／水流、Hornfel 与断线等待角色修复）。版本号尚未调整，未发布安装包。测试由一个执行者调度多个隔离游戏进程，不使用并行 agent；同组用例复用主客机和连接。

## 路线与 Boss 覆盖

[结局夹具](https://github.com/BMingSY/isaac-lan/blob/main/tests/state_endings.lua)将 Mother 起点准备为原生水一，之后使用原生出口推进。主客机分别记录实际楼层，通关也必须满足水一／二、矿一／二、陵墓一／二全部到达。羔羊支持 `--first-floor`，从普通第一层开始；其他终局保持各自的原生战斗、结局回调和会话清理断言。

[Boss 清单](https://github.com/BMingSY/isaac-lan/blob/main/tests/fixtures/boss_catalog.json)取自本地 J460 的 Boss、实体和房间目录，仅保存标识与名称，不包含游戏资源。覆盖 101 个可用 Boss 编号，另加七原罪及其超级版本、Ultra Pride、Krampus、两种天使的普通／堕落形态。107 个房间用例与 14 个终局／贪婪路线条目互补；未启用的 Raglich、Cadavra 单列，不计通过。范围不等同于穷举所有随机房型和冠军配色。

[房间夹具](https://github.com/BMingSY/isaac-lan/blob/main/tests/state_all_bosses.lua)使用原生 Boss 房间，保留地形、轨道及阶段机制；天使使用显式生成夹具。玩家保护、位置与分段伤害属于测试准备，胜负和清场由原生逻辑执行。每项检查主客机均看到存活且可见的目标、客机实体身份和位置、房间清场，并记录出现的 Boss 形态。控制台房间复用同一个负索引，因此每项先生成新楼层，避免复用已清空的房间缓存。

[执行工具](https://github.com/BMingSY/isaac-lan/blob/main/tools/run_bosses.py)支持 `--shard N --shards M`，各分片使用不同隔离目录与端口；`--case` 可重跑指定条目。[汇总工具](https://github.com/BMingSY/isaac-lan/blob/main/tools/check_boss_coverage.py)合并房间、结局和 Greed／Greedier 报告，缺项、缺少一端结果、失败或未恢复的报告均不能算全覆盖。为修正夹具而主动停止的批次，仅在引擎确认 SIGTERM 干净退出、目录恢复且同一用例两端都已通过时，由 `--partial-arena` 读取已完成项；崩溃、超时和未完成项不计通过。

所有运行保护并恢复隔离目录的配置、存档和日志，恢复后核对 SHA-256。既有手动双开目录未使用。性能与需要真实键盘焦点的验收单独执行。

## 本轮发现与修复

贪婪模式中，快照清理已消失的 NPC 会调用原生 `Room:Update()`，可能在共享状态已经恢复后再次推进波次。实机记录为客机 `expected=9 actual=10 tick=615 between_updates=true`。这会破坏快照应用后的状态一致性；绘制前已有的恢复不足以保证半帧应用边界。

[同步应用流程](https://github.com/BMingSY/isaac-lan/blob/main/src/bridge/sync/replica.lua)在房间清理后再次应用权威波次。[离线回归](https://github.com/BMingSY/isaac-lan/blob/main/tests/replica_pipeline.lua)先复现失败，再验证正常更新、半帧更新和重复快照。未增加网络字段、Hook 或原生布局，协议与 schema 不变。

Horny Boys 的客机崩溃位于 J460 渲染函数 RVA `0xbd198`，该路径按动画层读取 NPC `+0xbf0` 的持有炸弹容器。Hornfel 使用两个槽，Horny Boys 原生初始化使用三个槽；原有适配只覆盖 Hornfel。共享的 [Boss 适配](https://github.com/BMingSY/isaac-lan/blob/main/src/bridge/compat/bosses/held_bombs.lua)现按类型携带两个／三个稳定 ID，后端仍使用已校验的游戏 resize 与 `EntityPtr.Assign`，保持原生分配、观察者注销和销毁所有权。未增加 Hook；schema 升为 19，传输协议仍为 30。Lua 与原生 ABI 回归覆盖两种槽数、第三槽、重复恢复、删除、房间重建及非法输入；实机夹具逐槽比对实际引用并要求观察到全部持有槽。

Rotgut 第一阶段吞入角色后，原生 NPC AI 请求目标 `-14`、动画 `2`、空发起者；心脏战后的 `Room::Update` 自动返回同样不传角色。多人房间无法从当前玩家唯一确定发起者，两条路径均导致 `actor_unresolved`。新的 [Boss 策略](https://github.com/BMingSY/isaac-lan/blob/main/src/compat/bosses/rotgut.h)限定吞入目标、动画、方向、维度及实体形态，自动返回另要求来源为体内第二房间 `-15`、目的地为该房间记录的返回索引；版本后端通过现有队列转移该房间内的已连接角色，其他房间不参与。沿用现有房间所有权与原生换场，无新增布局或 Hook。最终实机确认主客机一起进入两段体内战斗，并在心脏死亡后自动返回原 Boss 房间，两端均记录 `RETURN source=-3 players=2`。

Rotgut 的早期第 8 轮夹具只检查离开体内，误把主机走向 I AM ERROR 房间也判为通过。该报告不计入覆盖；修正夹具为两名玩家都必须返回原索引，第 9 轮复现自动返回失败，第 10 轮在修复后通过。保留全部原始失败和被替代报告。

## 构建与离线检查

初始候选 `isaac_lan_probe.dll` SHA-256 为 `eb9c19a5783a6bcdb29628f712af3478764074c320817c16e32d519e1f14fa66`；贪婪修复后为 `20511c45fa75ccc0df6521e5d9e812a5f321abc91013b2a2e60ec54d758fa2a1`。每轮 runner 冻结自己的 DLL、脚本和哈希；已运行的非贪婪分片未被覆盖。

初始完整离线检查：格式、脚本和捆绑语法通过，81 项 CTest 通过；Python 148 项通过、19 个子用例通过、1 项失败。失败为已有 [LANBOT 过门问题 #58](https://github.com/BMingSY/isaac-lan/issues/58)，本轮参数为向左、speed 160、radius 15、offset 3、distance 95，360 帧未过门。未跳过或改写失败预期。Windows 网络／原生 ABI 38 项通过。

贪婪及持有炸弹修复后，完整 81 项 CTest 和 Windows 网络／原生 ABI 38 项通过；新增覆盖汇总／路线／分片／场景分类的七项 Python 检查与工具检查合计 44 项、19 个子用例通过。Rotgut 自动返回修正后，Linux 和 Windows 房间转换策略回归再次通过。格式、脚本和生成的组合夹具语法通过。

最终候选 `isaac_lan_probe.dll` SHA-256 为 `8942f0b59d07938ed5c8b47fde225b8fc1d81c2a2021f55a405483817d8c69de`；加载器为 `e893e7e8800dfbcab8cfd987962d4375e5c28b21ecaf2f30f6372820e634866c`，检查器为 `cef54b6e32d0e18bfb766a2bc9fef4ddff510b26f106a3494e38b446ee1d1c82`。未发布。

`response-final-r2` 在同一连接中通过输入、移动、过门、暂停、主动道具、蓄力武器及镜头七项检查。测试先使用直连，再切为单向 10ms（约 20ms 往返）延迟；主客机输入频率均为 60Hz。821 个输入观察样本中，发送与本机预览额外等待均为 0ms，75 次加速度输入切换均在同帧响应；这里测量的是输入采样后的处理等待，不代表键盘到屏幕的完整延迟。移动和镜头无反向跳步，过门最大位移 13.23，恢复暂停后无漂移。

第一轮响应验收的调度进程收到终止信号（退出码 143），未得到完整引擎报告。该轮不计通过；保存当时主客机日志，正常关闭该轮拥有的进程后，从原始备份恢复目录并校验哈希，再执行第 2 轮。

EID 场景的 `scenes-final-r1` 复用同一对进程完成持续举袋、两层流水和 8 轮反复举袋。Lua 场景断言与原生退出通过，但 Python 检查将所有非流水水花实体的峰值限制为 80，第一轮因超过该值而失败，原报告保留为失败。该计数混入雨滴、涟漪、雾、虫子等正常房间实体，不能判断流水水花是否重复同步。

`water-final-r2` 在同一构建上只补验两层水流，新增逐类型／副本标记记录；两层通过旧阈值及原生退出检查。检查器进一步改为直接要求流水水花的副本数量为零，保留其他实体总数作为诊断；新增离线反例确认 120 个无关实体不会误报，而一个被同步的流水水花仍失败。用最终检查器重新分析第 2 轮原始 CSV 也通过，无需再次启动游戏。流水向量读写边界、自然动画／销毁仍由实机夹具断言。
