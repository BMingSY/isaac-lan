# 多道具同步性能验证（2026-10-18）

本次针对持有大量道具、原地不操作时的卡顿，以及直接受影响的同步、精灵和生命周期链路。当前候选生产提交为 `22a74807dba32ceec095eb67ea2f523a37b6708b`，分支从 `refactor/test-harness` 创建；该基线合入主分支后，同步合入 `624461c`，随后合入仅涉及测试与文档的 `3bb143a`；拆分后的生产源码、构建配置、依赖与安装文件和冻结候选一致。本记录不是发版全量验收。独占窗口下五项静止性能场景均通过，七项直接功能回归双端通过。极限主动攻击的原生问题按用户确认移至独立分支 `fix/native-entity-pressure` 处理。

## 独占压缩对照

使用 `native-codec-exclusive-final-20261018-01` 的实际快照，在游戏全部退出后运行 Windows x86 Release 基准程序；每组预热 5 次、测量 100 次，逐次核对解压字节。证据为 `compression-win32-same-04` 和 `compression-win32-mixed-03`；方法见[诊断参考](https://github.com/BMingSY/isaac-lan/blob/main/docs/diagnostics-and-resource-testing.md#编解码基准)。

500 种道具的单个客机视图原始大小为 1,647,466 字节：

| 算法／发送路径 | 压缩字节 | 编码均值 / P95 / P99（ms） | 解码均值 / P95 / P99（ms） |
| --- | ---: | ---: | ---: |
| miniz 完整帧 | 240,899 | 5.790 / 5.987 / 6.226 | 2.149 / 2.305 / 2.397 |
| LZ4 完整帧 | 248,018 | 1.216 / 1.307 / 1.345 | 0.492 / 0.557 / 0.583 |
| Zstd 完整帧 | 155,433 | 1.304 / 1.401 / 1.560 | 0.928 / 1.026 / 1.186 |
| miniz 字节补丁发送路径 | 115,458 | 22.348 / 28.635 / 37.289 | 7.446 / 8.076 / 8.935 |
| Zstd prefix 发送路径 | 88,657 | 4.893 / 5.640 / 5.718 | 1.200 / 1.381 / 1.452 |

两种发送路径都计入完整帧候选和参考快照处理。Zstd 完整帧比 LZ4 小约 37%；prefix 路径比旧路径的编码均值降低约 78%，载荷减少约 23%。小包并非所有情况下都更小：空背包参考帧为 800 字节，旧补丁为 120 字节，但编码均值从 0.333 ms 降到 0.047 ms。

同视图的 3／4 人 CPU 工作量下，Zstd prefix 编码 P95 为 10.535／15.493 ms，旧路径为 57.677／87.369 ms；空背包、300、500 道具三个不同视图的 4 人工作量下，分别为 6.439／32.493 ms。这里是按接收者数量处理真实样本的 CPU 基准，不是实际三人／四人游戏。原始样本、程序哈希、各算法数据及 JUnit 保留在测试产物中。此前 `compression-win32-same-03`／`compression-win32-mixed-02` 未审计其他任务，仅作探索证据，不用于本结论。

## 实机方法

使用有归属标记的 `native-codec-host-20261018`、`native-codec-client-20261018` 和独立端口 52480。基线为测试框架冻结构建 `test-harness-build-20261017`，probe SHA-256 为 `a4086e36d7437cfe108a20e22216fce35978c74cf58100c810c5a1dc48d3137a`。

原地持有用例显式提交零输入，不攻击、不移动；各用例目标为 1100 tick，从第 150 tick 起记录逐帧间隔及采集／应用耗时。双方渲染样本不得少于 100，P95 预算为 33.333 ms。基线和候选均关闭生产默认不开启的详细阶段计时，保留夹具的逐帧及采集／应用测量；没有降低同步频率、状态精度或道具负载。

当前启动环境继承 `PreferSystem32Images`，自动代理加载未成功。因此本专项使用隔离注入入口，不计为自动加载通过；没有修改系统安全策略。每组复用同一对主客机进程，用例之间恢复夹具状态。

## 功能与一致性

`native-codec-functional-20261018-07` 使用当前候选，依次完成原生字段／动画对照、客机复活外观和连续移动；两端全部通过，均退出码 0、堆转储 0，资料恢复哈希一致。主客机各启动一次，三项复用进程，单程模拟延迟 75 ms。

- 原生字段用例逐字节对照泪弹、跟班、效果实体的批量采集和紧凑编码，以及客机通过 Lua、原生数组、紧凑字节三条路径写入的结果；检查畸形输入拒绝写入、动画推进／回退／恢复。
- 客机外观用例覆盖分房、道具拾取、死亡、Boss 清场、远端复活、独立背包、层状态、阴影和实体身份／位置。原断言将客机拾取的奖励算在主机背包中，已分别核对两人的背包与客机库存。
- 移动用例检查连续输入、身份、位置与绘制姿态。录像核对复活后的双端角色可见，以及移动中的身体／朝向；帧标识为主机 139／141／207、客机 101／103／169。
- 原始 TCP 回放 `native-codec-replay-07` 还原 262、672、1062 份状态；实际载荷 254561、1208908、932702 字节，对应当前完整帧 810372、2795372、2843859 字节。回放只证明状态链路正确，不能替代实时性能测量。

`native-codec-functional-20261018-08` 使用同一冻结候选，依次完成 Forget Me Now／五点骰子／R Key 换层、全队沙漏与跨层回退、里拉撒路形态／矿道／Birthright、分房与换层后的本地 HUD；两端四项全部通过。主客机各一次启动，退出码均为 0、堆转储均为 0，资料恢复哈希一致。录像核对矿道战斗中的双端角色与本地 HUD，帧标识为主机 418／565、客机 379／525。对应 `native-codec-replay-08` 四条连接成功还原 834、1181、1121、999 份状态。

失败证据保留：`functional-01` 的移动、换层道具和沙漏已完成，但里拉撒路因隔离存档未解锁而未进入玩法；`functional-02` 的里拉撒路／HUD 通过，外观首帧失败；`functional-03` 缺少夹具大厅就绪通知；`functional-04` 的测试泪弹在验证前消失；`functional-05` 明确定位空动画挂点游标差异；`functional-06` 修正游标后在旧奖励归属断言失败。未进入或未完成的后续用例不计通过，修正后另开轮次。

测试框架合入 `3bb143a` 后，对道具审计、原生套件、触发器和跟班检查执行 193 项 Python 回归，全部通过；两个注入启动参数共享同一行为，并保留严格的整组完成判定。
