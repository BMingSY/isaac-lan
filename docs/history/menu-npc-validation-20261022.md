## 验证结果

| 范围 | 结果 |
| --- | --- |
| 地址输入 | 实际向客机所属窗口发送 M/F，字段收到 `mf`，音乐／音效音量与全屏状态不变；随后删除并正常输入 IP、确认加入 |
| 其他字段 | 两端输入非法端口后继续编辑为有效值；主机输入种子，通过菜单准备和开局；手柄确认／返回与文字输入分离 |
| 大厅聊天 | 主机按 `~`、输入文字、Enter、`~`，开局前主客机均收到同一消息；画面留有对应聊天记录 |
| NPC 权威与显示 | 同一对进程连续运行蜘蛛、冲锋怪、攻击蝇。主机记录 756 个采样，客机记录 1453 个显示采样；三种 NPC 的原生追踪目标均为有效玩家，冲锋怪在两名玩家间切换目标。双端完成标记齐全 |
| 延迟与退出 | UDP 每方向注入 40 ms，画面 RTT 约 81 ms。主机 PID 27660、客机 PID 20568 均退出码 0；heap watch 无异常转储，配置、存档及日志逐文件恢复哈希一致 |
| 离线与构建 | Windows x86 构建通过；9 项直接相关 CTest、34 项离线状态用例及 46 项工具／资料保护用例（另含 19 个子用例）通过。最终 NPC 数据扩展后再次单独通过回放；格式与差异检查通过 |

回放对同一份权威观测分别启用线性显示和 NPC 制动显示，以 40 ms 单向延迟、60 Hz 绘制比较位置误差。两条蜘蛛轨迹的制动阶段误差分别减少 25.1% 和 22.7%；合并相邻快照时分别减少 18.9% 和 16.9%。整段轨迹误差减少 9.7%～16.6%。冲锋怪结果一致；攻击蝇整段误差变化在 1% 内。此比例只描述冻结样本，不代表任意怪物或链路的改善保证。

实机采样没有发现客机另行计算追踪目标：NPC AI 和碰撞由主机推进。客机本机角色预测位置可能领先于主机已收到的位置，快速变向仍可能产生短暂相对位置差。制动显示只减少已经观测到的减速过冲，不能预知下一次急停、转向、攻击或碰撞。

## 失败、重启与边界

- 基线第 1 轮在进入标题前退出，未取得轨迹，不计通过；保留启动记录。第 2 轮成功采集，冷启动退出原因尚未定位。
- 候选第 1 轮缺少菜单输入文件消费逻辑，菜单驱动超时；第 2 轮补充消费后因 `--no-luadebug` 禁用 `io` 而失败。两轮均正常关闭所属实例并恢复资料。第 3 轮在隔离环境启用 LuaDebug，复用同一对进程完成所有菜单与 NPC 场景；工具拒绝不兼容的菜单／LuaDebug 参数组合。
- 补充第二条轨迹时，沿用首条轨迹的“整段改善至少 10%”断言未通过：隔包实际改善为 9.7%，制动部分改善 16.9%。未改生产模型；回归同时保留两条轨迹，以制动阶段至少改善 15%、整段至少改善 5% 为固定样本检查，另保留其他 NPC 不显著退化的约束。
- 因上述启动／夹具失败，重启了对应所属实例；成功轮内部不重启、不更换连接。未操作用户正式游戏实例。
- 真实 IME 候选窗口、任意第三方 Mod 自行读取系统按键、全部怪物／Boss 及压力场景未在本专项遍历。输入法组合、焦点释放、长地址、键盘重复／松开、重复状态、缺包、反向、传送及视图清理有离线覆盖。
