## 执行、退出与恢复

一个执行者调度两对有归属标记的隔离实例：`all-room-gather-host/client-20261027-pr` 与 `test-harness-host/client-20261017`。每轮主客机各启动一次，轮内复用进程与连接；结局之间使用原生退出和菜单恢复，不重启游戏进程。Boss 整组没有中途重启。没有控制用户手动游玩的实例。

基础组使用端口 35700；Boss 使用 35710／35711，每方向延迟 20 ms；最终特殊路线使用 35740／35741，结局使用 35720／35721，两者每方向延迟 75 ms。开启堆异常监测和必要双端录帧；本次不作性能结论。

最终四组所有游戏与堆监视器退出码均为 0，异常转储数均为 0。收尾再次核对四个隔离实例的 12 个受保护目录，配置、存档与日志等逐文件哈希一致，所属游戏进程全部结束。

## 失败轮次与修订

| 轮次 | 原始结果与处理 |
| --- | --- |
| `basic-01` | 安装器执行成功，但 WSL 启动链继承的 DLL 搜索策略为 4，加载了系统 WINMM，自动加载失败。改用 Windows 桌面 Shell 启动同一隔离 runner 后，`basic-03-desktop` 安装冒烟及 `basic-04-desktop` 完整组通过；没有修改系统策略 |
| `basic-02-injected` | 前六项完成后，监督进程收到中断，后端进入收尾；主机在原生输入设备断开回调崩溃，退出码 C0000005，保留一份完整转储，客机正常退出。整轮失败，不计安装自动加载通过；完整基础组随后另开轮次复测 |
| `routes-01-desktop` | 超级贪婪在结局宝箱处超时，未取得该结局证据。夹具改为先清开两名玩家，再使用正常客机输入接触宝箱 |
| `routes-02-desktop` | 上一项夹具修订引入嵌套玩家作用域，原生接口拒绝调用。改为顺序访问两名玩家，并使离线替身执行相同的禁止嵌套约束 |
| `routes-03-desktop` | ??? 在子宫二光柱出口等待换层超时。夹具改为用正常客机输入进入光柱，并在原生入场动画开始后停止干预位置；最终六结局组通过 |

上述三个失败路线组的双端均需要强制收尾，退出码 FFFFFFFF，转储数为 0，不能计为正常退出通过；所有失败轮次的资料恢复均通过。修订后将四项特殊路线和六条结局拆为两组并行复测，最终成功报告独立保存，没有把旧失败报告覆盖为通过。离线修订期的失败与旧夹具对照也保留在批次产物中。

## 已知问题与范围边界

- **偶发未定位**：`basic-02-injected` 的中断来源及随后退出异常尚未完全解释。转储定位到游戏 RVA `0x513795` 的输入设备断开回调，栈包含原生后台设备枚举和扩展枚举包装；最终普通退出未复现，不能据此宣称该中断路径已修复。
- **仍可复现的既有画面差异**：Ultra Greedier 击败后主机显示金色地板与金币贴花，客机保留木地板；本批次 `routes-03-desktop` 主机帧 1790／客机帧 1754 可见。通关与清理断言另行通过，画面差异不计一致通过；与[此前记录](https://github.com/BMingSY/isaac-lan/blob/main/docs/history/2026-11-01-release-routes.md)相同。
- **未执行**：道具／角色／Mod 专项、全道具／卡牌／药丸遍历、压力与性能、输入响应／镜头专项。已有开发专项及其未决问题保持原记录，本次默认项通过不扩展为这些领域全部验证通过。

- `manual-dual/20261108-094940-349539` 与 `20261108-095716-098631` 均因客机角色不可用失败，失败证据和备份保留，两轮均已恢复。

- 用户关闭两端后状态为 `closed`、`restored=true`；再次读取六个受保护目录，逐文件哈希与启动前一致。
- 最终离线轮 `offline-manual-final-05` 的格式、语法、163 项 CTest、671 项 pytest 和 45 项子测试通过。定向用例覆盖原生菜单就绪前不联机、避开删档行、角色资格保留其他进度、失败收尾与资料恢复。
- 工具修复没有改动生产源码、CMake 或 VERSION；59 项冻结 EXE／DLL 与当前构建仍逐项一致，沿用上述 DLL 与安装包。此补充回归不扩展默认发布验收范围。
