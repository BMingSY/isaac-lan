## 根因与修复

| 问题 | 定位与处理 |
| --- | --- |
| 里拉撒路形态不同步 | 客机实体回收调用原生房间更新，清房回调再次触发 Flip，覆盖已经恢复的权威形态。客机联机房间启用期间跳过玩家清房玩法回调，主机、单人和加载路径保留原调用。Lua 没有可阻止该原生前置行为的接口，新增 J460 入口受签名校验，不改对象分配与所有权。 |
| 木十字架多挡一次 | 联机存档拦截跳过了 `CaptureState` 中的离房临时效果清理；原版随后恢复进房效果，令护盾重复。保留内存采集及清理，只拦截单人存档文件写入，复用现有原生能力。 |
| It Lives 连续进房失败 | 旧录像中主机已在上一场 Chimera 中死亡。定向重现该幽灵状态后，角色进入 Boss 房约 46 ms 即被 `finishFrame` 的幽灵跟随逻辑带回存活队友所在房间，随后出现相同进房断言。修正静止观察夹具的伤害保护，并在实际发生死亡的场景立即断言；正常幽灵跟随规则保留。 |
| 玩家泪弹缺失中止会话 | 只容忍直接由玩家生成、无子实体或矿车链接的泪弹创建失败／被原生池回收；本视图不循环重建，后续视图可恢复。其他必要实体继续严格检查，缺失数量由 `missing_player_tears` 记录。 |

压力复测独占一对实例。500 种道具档实际为双端各 501 个道具，帧间隔 P95 为主机 245 ms／客机 105 ms；500 泪弹档实际为双端各 500–501 个泪弹，P95 为 70／40 ms。缺失泪弹的诊断采样最大值均为 0，因此这两档的实机结论是“本轮未复现”，容错分支和后续恢复由离线强制淘汰／创建失败用例覆盖。

两轮完整分片尝试均未计为通过：诊断轮完成 52 项后，外层执行进程以 143 退出，未完成最后一场与报告收尾；修正夹具的补充轮完成 33 项后，在定向复现已确认根因时主动停止，正常退出。两轮部分结果均保留，不替代全 Boss 或发布验收。

## 清理与保留项

诊断、正式修复 DLL 和不同夹具需要独立启动；同组用例复用主客机进程和连接。两组诊断使用了强制关闭：原长序列的外层执行进程终止后，所属双端无法正常关闭；幽灵定向诊断触发预期断言后也未正常关闭。两组均核对 PID、路径与归属标记后关闭，未产生原生异常转储，恢复结果单独保留。其余已完成组正常关闭。

13 个诊断／验证组的 18 个受保护目录均按备份逐文件核对恢复，所属实例全部关闭；最终核对见 `final-restoration.json`，不控制手动游玩实例。画面抽查见 `visual-review.json`，不将全部归档帧都计为人工审阅。

网络编码耗时与高负载卡顿留待后续版本。织布魔偶分房、错误技历史随机崩溃等范围外问题沿用原状态，全道具逐项验收保持暂停。
