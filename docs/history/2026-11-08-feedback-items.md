## 反馈核查与归因

本次拉取 3 条 v0.6.3 反馈，ZIP 大小及 SHA-256 逐份核对通过；19:10 再次检查服务器时没有新的未收取项。服务器原件保留，私人日志不进入仓库。多份报告重复携带的会话按原始日志位置去重。

| 反馈／现象 | 证据与处理 |
| --- | --- |
| 蓝钥匙过道出口异常，丢弃后仍进入蓝房间 | 客机门请求直接排队邻接房间，跳过权威的原生过道初始化；逐角色迁移也未在源房间消费门目标的重定向标记。修复复用权威转场解析，并在源房间离开通知中清理该标记。 |
| 骸骨魂石使金币、炸弹、钥匙归零 | 临时身体在登记前广播构造初始资源，覆盖已有队伍数量。未登记身体先从有效参与者继承本次共享资源，再执行原生广播；没有在用卡后补发资源。 |
| 客机里以撒切换／替换时未显示选中项 | 道具数量不能表达旋转后的库存顺序；恢复顺序还需刷新原生 HUD 缓存。同步有序道具 ID，映射到本机已有历史索引，保留原生对象所有权。 |
| `261108-VEKZ`：里骨只显示骨棒；`261108-A8RQ`：分房后重连 | 去重后的相关日志出现持有实体缺失或自引用错误。角色关联原先在当前视图房间按本机索引查找，分房时可能指向其他实体；改为在该角色所属房间内采集。离线用例在修复前失败，最终实机分房抱起、投掷、跨房和重聚通过。 |
| `261108-KQQF`：Boss 复活后倒地，出门卡住 | 对应主分支已有的身体名单修复，见[复活专项记录](https://github.com/BMingSY/isaac-lan/blob/main/docs/history/2026-11-08-character-revival.md)。本轮再次验证骸骨与里骸骨的主客机复活链路。 |
