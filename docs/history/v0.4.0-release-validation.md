## 本轮新增修复

原生 J460 `RoomTransition.ChangeRoom` 仅在 animation 12 恢复 GameState。贪婪／贪婪模式加强版首访出生房的沙漏实际选择 `index=-2, direction=0, animation=3, dimension=0`，传送到 I AM ERROR 房并保留当前库存。旧适配无论原生选择什么动画，均在转场后恢复检查点的位置，导致特殊传送被拉回旧房间。

[回退后端](https://github.com/BMingSY/isaac-lan/blob/main/src/engine/versions/j460/rewind.cpp)现只在实际选择 animation 12 时恢复检查点位置；其他动画及提前返回沿用原生结果。复用现有选定参数和 `resumeAfterTransition` 接口，未增加 Hook、内存布局、分配／释放或网络字段。Home 原有互斥路径保持原契约。协议仍为 28、WorldState schema 15、联机存档格式 `IsaacLAN/save/3`；构建一致性由实际 DLL 的扩展指纹隔离。

修复前 [ABI 回归](https://github.com/BMingSY/isaac-lan/blob/main/tests/rewind_home_test.cpp)的 Greed 用例可复现错误；修复后 19 组通过，新增主／客机对所有合法动画 0–22 的位置恢复检查，并核对原生特殊房提前返回需要 Type 16 **且** StageID 35，两项各自成立不触发该分支。

[联机菜单](https://github.com/BMingSY/isaac-lan/blob/main/src/bridge/presentation/menu.lua)只按原版 `PlayerType` 显示中文名，保留原生角色列表、存档资格、表／里配对和画像；角色 Mod 名称使用原目录名称。菜单离线检查覆盖原始英文名、表／里角色、雅各与以扫／里雅各差别，以及与原版英文同名的 Mod 角色。74 项 C++／Lua 与格式、语法检查在汉化后再次通过。

客机退出联机后，原生菜单可能停在标题页，同时 Manager 保留已选存档。旧判断仅凭菜单场景和已选存档提前显示联机界面，输入却只在 `MainMenu.Update` 中接管，导致 Escape 操作原生退出确认。第 09 轮画面复现这一问题。现有原生菜单读数足够，复用 MenuManager 指针及当前页 `0x40`；新增[只读菜单上下文](https://github.com/BMingSY/isaac-lan/blob/main/src/engine/versions/j460/menu_context.h)，仅在原生主菜单（页 3）准备好后允许显示。没有新 Hook、写入或对象所有权变更。[回归测试](https://github.com/BMingSY/isaac-lan/blob/main/tests/frontend_menu_test.cpp)直接调用生产判断，覆盖标题、存档、选角、主菜单、场景及释放边界，并加入 Windows CI。

## 集中实机

使用 [发布验收 runner](https://github.com/BMingSY/isaac-lan/blob/main/tools/run_release_acceptance.py)，真实安装器装配自动加载入口，所有 Workshop Mod 关闭。游戏版本为 Repentance+ `1.9.7.17.J460`。每轮两端各启动一次并复用进程，在场景之间存退至菜单，清理回调及输入后继续。测试前保护完整资料，客机仅在启动前临时解锁抹大拉以验证暂停菜单；结束后恢复并核对哈希。人工测试窗口未操作。

第 01 轮保留为失败：普通操作和跨层沙漏完成，贪婪特殊传送及库存检查通过，但移动准备把玩家放在 ERROR 房下方出口附近，意外触发下一层。客机拒绝额外楼层事件，回调异常使其无法正常退出，需强制结束；不是一次通过的堆或退出验收。两端资料均恢复。夹具将移动路径移至房间上方，格式和语法检查通过后重启进行第 02 轮；冻结原生文件没有改变。

第 02 轮（主机 PID 9720、客机 PID 32528）前七项通过，`completed-seven-cases.json` 核对双方恰好完成场景 1–7，暂停断言完整，缺失的标记仅属于第八项。第八项尚未进入单机：验收工具在关闭联机界面后只按 Escape，退到标题页并打开原生退出确认，未到达主菜单。工具按失败路径自动清理进程；两端退出码均为 0、heap watcher 为 0、转储 0，完整资料恢复一致。该轮整体结果仍为失败，不把七项通过改写为八项通过。

修正导航为有弹窗时 Escape 关闭、标题／存档页 Enter 前进、其他页面回退至主菜单；每步读取原生菜单状态，不写菜单或 Manager 字段。runner 支持选择剩余场景，后续仅补测单机存档链路，避免重复执行已通过项目。

第 03 轮仅启动主机，因单机夹具独立运行时未发送启动 `MENU_READY` 握手，工具在启动阶段超时并关闭主机，客机未启动。退出码与 heap watcher 均为 0，资料恢复一致；没有记为单机验收通过。补充握手后，离线执行实际夹具确认启动信号及首个 GUI 请求均只发送一次；一／八场景组合均通过 Lua 编译。

第 04 轮已进入两端原生新开局，但客机仍在加载画面时按固定渲染帧数检查控制状态，提前中断。离线加载阶段用例复现旧夹具过早准备库存；修正后等待原生角色可操作，原断言和阶段超时保持有效。第 05 轮主机完整链路通过，两端单机存档字节保留，客机的 Continue 按键被仍显示的联机覆盖层接管，最终阶段超时。第 06 轮新候选包的基本操作通过，固定两次 Escape 仍不能可靠区分覆盖层与底下的原生主菜单，单机导航中断。三轮整体均保留失败；进程正常退出、无堆转储、资料恢复一致。

第 07 轮通过正常 Online 入口打开大厅，两端中文选角画面通过；两端单机存档字节保留，主机 Continue 完成，客机返回菜单仍失败。第 08 轮在保护备份阶段中断，未启动游戏或修改受保护资料。第 09 轮改用正常前台键盘输入仍复现同一问题，原生退出确认覆盖在联机界面上，结合只读菜单状态定位到上述生产判断。第 07、09 轮进程正常退出、无堆转储，完整资料恢复一致；失败结果原样保留。

夹具观察原有 `_IsaacLanMenuRender` 的返回值，将覆盖层实际显示状态交给导航工具；未改变其返回值。导航先按原生标题／存档页前进，再在主菜单关闭联机覆盖层。联机大厅用正常 Online 入口打开并录制两端画面，再在同一对进程内执行原生 Continue；不写菜单或 Manager 字段，也不使用原有内存改写式单机夹具。

第 10 轮使用第 03 候选包，主机 PID 9764、客机 PID 10588，复用同一对游戏进程完成剩余单机链路，两端全部断言通过。两端均由原版 New Run 开局、暂停菜单存退，参加联机后再从原版 Continue 恢复：种子分别为 `TAGT XQEM`、`J7FK QLT2`，角色、37 硬币／4 钥匙／3 炸弹、红心及悲伤洋葱／五芒星数量不变；联机过程中两端原生单机存档 SHA-256 均不变。客机仅在原生主菜单准备好后返回联机界面，可正常关闭后 Continue。两端中文大厅选角及单机恢复画面已人工核对。两端进程退出码及 heap watcher 均为 0、转储 0，完整受保护资料恢复一致；该轮 `report.json` 为通过。
