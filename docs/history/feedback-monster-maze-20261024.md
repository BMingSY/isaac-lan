## 怪物反馈与预测边界

基线中，普通泪弹的显示已经经过 Horf，客机还没有受击闪色；直到伤害快照到达才显示红色。21 轮首次主机伤害回调时间为 11752998 ms，客机首次红色为 11753089 ms，期间相差 91 ms。本地泪弹预览、位置外推已经存在，本地命中与受击演出事件没有实现。

另一个可复现问题发生在击退减速包到达时：基线首发击退窗口，主机实际显示的最大 X 为 319.39，客机达到 326.42，再向回修正。23 轮中采用实际上一帧显示位置作为修正起点后，同一类窗口主机最大 X 为 319.91，客机为 320.35。两轮原生碰撞轨迹有微小差异；离线回归另用完全相同的 Horf 击退数值检查旧速度不能多推进一步，并保留蜘蛛、冲锋和转向飞虫的既有误差预算。

撤回闪色方案后的最终 27 轮，该窗口主机最大 X 为 319.79、客机为 320.80；受击着色仍在权威状态到达后出现（主机伤害回调到客机首次红色相差 96 ms）。六类战斗场景共记录主机伤害回调 20 次、客机 0 次，致死目标退场，不可受伤和打空目标存活；高射速段实际连续命中间隔约 3—4 tick，普通段约 11—14 tick。客机没有提前闪色采样，符合本轮未实现受击预测的明确范围。

当前架构的核查依据：

- [replicaEntityUpdate](https://github.com/BMingSY/isaac-lan/blob/main/src/engine/versions/j460/rooms.cpp) 在客机跳过普通实体的原生更新，只有明确分类的本地环境效果例外。
- [实体恢复](https://github.com/BMingSY/isaac-lan/blob/main/src/bridge/sync/entity_codec.lua) 应用主机的实体、精灵、颜色与原生动画姿态，并关闭副本碰撞；它没有单独的命中确认事件。
- [攻击显示](https://github.com/BMingSY/isaac-lan/blob/main/src/bridge/presentation/attacks.lua) 预测普通泪弹绘制及武器显示；[运动呈现](https://github.com/BMingSY/isaac-lan/blob/main/src/bridge/presentation/motion.lua) 负责本地位置预测和远端运动外推。二者不等同于完整的玩法回滚。

由此不能直接打开客机实体更新或调用 `TakeDamage` 来补动画，那会同时运行玩法。后续受击预测需要独立的事件身份、确认／拒绝和去重，以及可本地推进的表现时钟；还需处理原生受击着色与基础外观叠加、Mod 拒绝伤害、重复／合并快照及跨房清理。此处是未实施工作的核查结论，未记为已完成设计或修复。

最终实机夹具为 [state_monster_feedback.lua](https://github.com/BMingSY/isaac-lan/blob/main/tests/state_monster_feedback.lua)：同房近距离、分房远距离、致死、不可受伤、打空与高射速普通泪弹六类场景，记录受击和死亡姿态，确认伤害只在主机执行。普通 Horf 没有在本轮呈现独立名为 `Death` 的动画，实际死亡消失和碎片已记录；不扩展为所有怪物死亡动画都通过。
