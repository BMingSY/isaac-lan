## 最终实机结果

`special-motion-final-20261018-05` 双端通过，使用上述冻结 DLL 和夹具，每方向 75 ms 延迟。单组主客机连续执行以下检查：

| 场景 | 结果 |
| --- | --- |
| 里骸骨静止 | 灵魂移动时骨架保持主机位置，不跟随灵魂输入；客机至少 10 次断言通过。 |
| 抱起与投掷 | 灵魂抱起时原生持有引用存在，投掷后清空；队友同样可抱起／投掷。双端画面显示完整骨架和骨棒，不再只显示漂浮武器。 |
| 飞行与地下室 | 飞行实际越过 SOLID 地面障碍；客机正常走下梯子进入地下室，至少 5 次检查确认其显示跟随横版权威轨迹。 |
| 普通角色 LTL 入口 | 通过真实方向输入从房间 83 走入 82，分别检查目的地无人和已有队友两种状态，均从 RIGHT0 入口落在 `(1080, 280)`，双端位于有效区域。 |

检查原生画面：主机／客机帧 249／111 为静止骨架，276／138 为灵魂抱起，309／171 为队友抱起；客机帧 228 为地下室，主机／客机帧 797／656 为幽灵随队抵达 LTL 的有效区域。主机在地下室检查时留在普通房间，不能把主机画面当作地下室视角。

主机 PID 50252、客机 PID 29132 均正常退出，退出码为 0，堆监测退出码和转储数均为 0。`special-motion-final-protected-20261018-05` 恢复配置、存档和日志，74 个文件哈希与运行前一致，`restored=true`。此轮重新启动是为了加载修正后的确定性夹具；轮内未重启进程。

## 中间失败和额外扫描

- `door-diagnostic-20261018-01` 的夹具在楼层事务未完成时继续改层，未执行落点检查并触发强制关闭；02 等待原生楼层就绪后完成一条 LBL 正常走门检查。
- `special-motion-candidate-20261018-01` 在抱起准备时把里骸骨的 `GetSubPlayer()` 当成灵魂，空值导致夹具失败。按同控制器的灵魂角色查找后继续验证。
- `ltl-door-20261018-01` 在限定时间内未生成目标朝向，超时；客机清理需要强制终止。02 的两层没有找到 LTL，按夹具断言停止，两端正常退出。这两轮没有验证目标入口。
- `special-motion-ltl-20261018-03` 确认灵魂和队友抱起的实际画面、投掷释放、地下室以及两种外侧入口，但在额外扫描门槽 6 时走门超时，整轮失败；该额外路径未完成，不计为通过。
- `ltl-door-20261018-04` 用原生红房间 API 增加内角邻居。左侧内角两次通过；夹具随后从同一邻居的错误方向走门，却按上侧入口断言，整轮失败。`special-motion-final-20261018-01` 修正方向后，两个内角各两次通过，后续扫描未找到外侧反向门，整轮仍失败。
- `special-motion-final-20261018-02` 使用未修改的原生布局，正常走过右侧入口两次，但另一个邻居未找到反向入口，整轮失败。后续核对日志发现当时有迷宫诅咒，准备场景时请求房间 106，实际进入 118。额外扫描并未全部完成，不以其部分断言代替全门位覆盖；最终专项固定为已复现用户问题的原生右侧入口及幽灵跟随路径。
- `special-motion-final-20261018-03` 的主机已确认幽灵落在 `(1079.47, 280)` 且位于房间内，但夹具结束普通门列表后把后续幽灵检查的目标编号发送成 `-1`，客机断言失败。修正测试元数据后另开新轮，保留该失败。
- `special-motion-final-20261018-04` 在幽灵场景准备阶段再次被迷宫诅咒改送：请求房间 83，实际进入 70，因此找不到预期返回门。该轮没有完成幽灵检查；两端退出码和堆转储均为 0，资料恢复通过。最终夹具清除本专项不检查的楼层诅咒，保留原生房间布局和真实走门输入。
- 上述产物和失败均保留。每轮内复用主客机进程；轮次间因原生 DLL 更新、夹具失败或冻结场景不同重新启动。每轮外层使用 `ProtectedLabs` 备份并逐文件核对恢复；强制退出的两轮不计为正常退出。
