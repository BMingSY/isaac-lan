# Boss 出场共享与客机纠偏专项（2026-11-08）

Boss 出场尚未结束时，后来进入的玩家现在接收同一场动画；首位观看者结束后，后来者跳过剩余部分并进入战斗。客机的大幅位置纠偏限制为每秒 120 个游戏坐标单位，当前移动输入独立积分。本记录是两项反馈的开发专项。

## 查证与失败保留

基线中，第一名玩家创建 Boss 房间并触发出场事件，事件只登记当时的观看者。第二名玩家进入已加载房间时没有再次经过出场通知，因此共享房间暂停却没有对应画面。`baseline-03` 在主机先入场、客机稍后入场时命中 `Late entrant never saw the shared boss intro`；主机正常退出，客机清理需要强制终止，该轮不计为通过。

`baseline-01`、`baseline-02` 分别缺少隔离存档夹具和堆监测工具，属于环境准备失败。`fixed-01` 的动画已在双方显示，但夹具持续检查跨到了自身下一次主动迁移的边界；该轮保留为失败，双方清理均需要强制终止。夹具改为在稳定窗口完成一次控制恢复检查，保留动画、去重和房间断言。

`fixed-02` 验证了双方播放及控制恢复，随后结束规则调整为由先进入者决定。最终轮将两次入场错开 40 tick，并要求后来者的实际播放时长比完整播放至少短 20 tick；没有用前一轮通过替代最终规则的验证。

移动离线用例在基线命中 `Late authority correction exceeded its display speed budget`，修改后通过。限速实现复用 [PR #154](https://github.com/BMingSY/isaac-lan/pull/154) 中的移动修正，并补充 30／60／120 Hz 下的二维距离检查。玩家日志没有连续位置与网络时序，无法据此确认其每次抖动都来自同一原因。

## 最终验证

11 项定向 CTest、70 项相关 pytest、代码格式和脚本语法检查通过；Windows x86 构建通过。`native.intro-completion` 在 Linux 和 Windows x86 均通过，检查原生两阶段收尾、重复完成以及普通门／其他转场不被改写。

`fixed-03` 在同一对受保护进程中连续执行 `shared-intro` 和 `input-response`，双方各启动一次，端口为 `35140/35141`。每方向增加 40 ms 延迟，开启堆监测和双端 100 ms 录帧。第二个场景复用进程，测试协调器按场景重新建立会话；没有中途重启。使用隔离注入启动，不计为自动加载验收。

| 场景 | 实机结果 |
| --- | --- |
| 主机先进入 Boss 房间 | 主机从 tick 99 播放至 200；客机从 140 播放至 201。后来者在首位完成后的 1 tick 收起动画 |
| 客机先进入 Boss 房间 | 客机从 tick 600 播放至 699；主机从 639 播放至 702。后来者在首位完成后的 3 tick 收起动画 |
| 去重、异房隔离与恢复 | 双端每轮仅播放一次；未进入的玩家不显示其他房间的出场画面；双方控制恢复检查通过 |
| 移动输入与纠偏 | 820 个绘制样本、75 次输入切换；发送与预测显示均在同帧，75 次均在同帧响应加速度变化，纠偏速度峰值为 120.0 |

画面抽查了第二轮出场时主机第 427 帧／客机第 277 帧，以及恢复战斗后的主机第 444 帧／客机第 294 帧，确认双方原生 versus 画面和结束后的 Boss 房间。双方退出码均为 0，堆监测退出正常且转储数为 0；配置、存档和原日志恢复并逐文件核对哈希通过。

移动检查覆盖此处的纠偏上限、输入响应与原生惯性。部分转向后的位移响应超过分析器五帧观察窗口，不能把输入与加速度同帧响应表述为所有转向都立即产生同向位移。未复现玩家原有网络环境，也未遍历其他过场动画或第三方 Mod；本轮不属于完整发布验收。
