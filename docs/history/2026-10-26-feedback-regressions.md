## 查证与结果

| 反馈 | 旧版证据与定位 | 候选验证 |
| --- | --- | --- |
| 持有血田的玩家同房时客机崩溃 | 反馈调用栈为角色属性重算 → 地面碰撞查询 → 空房间描述符，故障 RVA `0x3f0806`。普通血田同房／分房探针没有直接崩溃；`blood-cache-baseline-01` 在血田持有者分房、移除飞行道具后，于客机 `RemoveCollectible` 恢复链中崩溃，暴露同一个未初始化房间上下文的网格尺寸问题。额外的强制属性重算尚未执行就已崩溃。 | 血田原生泪链实际生成；两种持有者分房及重聚、移除飞行、远端角色原生 `EvaluateItems` 与清理通过。空壳借用有效描述符并初始化空网格尺寸；升级为可见房间时重新初始化背景。 |
| 集合进入地下室后误入错误房 | `dungeon-outside-baseline-01`：入场者到 `-4`，队友保留来源横坐标约 570，随即从地下室进入 `-2`，集合又把全队带入错误房。 | 队友从来源房间右侧集合到地下室内的队友位置；停留、原生梯子返回原房、改由房主发起再次传送进入均通过。 |
| 里拉撒路看不到生命逆转阴影 | 底座的原生第二个 Sprite 不在原有副本状态中，客机又不执行底座 AI。`flip-baseline-01` 的主客机画面对照确认阴影缺失；该探针的完成标记仅表示场景完成，不代表阴影正确。 | 客机阴影可见性、路径及完整原生 Sprite 字节与权威快照一致；实际使用生命逆转后继续一致，移除效果后隐藏。双端画面核对可见阴影与清理结果。 |

血田反馈的原始 Mod 组合与续玩存档未完整重放，因此不将“血田本身必然导致崩溃”作为结论。修复依据是反馈的原生调用链、远端房间对象缺少初始化的代码证据，以及独立触发同类库存恢复故障的实机复现。生命逆转仅验收阴影显示，不扩展原有道具清单中尚未确认的双面拾取机制。

## 失败、复测与恢复

| 轮次 | 结果与后续处理 |
| --- | --- |
| 初始注入探针 | 启动失败，未进入玩法；改用隔离目录自动加载。 |
| `feedback-fixed-01`、`02` | 首次地下室落点与梯子返回通过，第二次人工楼梯接近未触发预期入口，夹具中止；不能计作完整通过。重复进入改为显式房间传送，仍覆盖第二位发起者和集合落点。 |
| `feedback-fixed-03` | 地下室检查通过，但血田移动探针再次踩入前一用例遗留的楼梯，泪链前提失效；补齐用例间入口清理。 |
| `feedback-fixed-04` | 血田泪链、分房／重聚及原生属性重算通过；空壳转为可见房间时发生背景渲染异常。修正空壳的绘制缓存初始化边界后重建。此前失败中止阶段观察到的同址原生渲染异常一并保留在证据中。 |
| `feedback-fixed-05` | 三项反馈的断言、画面和干净退出通过；复查日志发现完成标记早于原生换层事务完成，不能计入换层通过。保持原报告，夹具改为等待房间和权威视图均就绪。 |
| `feedback-fixed-06` | 全部定向检查、换层完成、保存和退出通过。 |
