# 队伍兼容与合成袋验收

记录队伍兼容与合成袋的原验收轮次；协议 26、schema 15。结果只适用于所列构建和夹具，当前实现见[队伍兼容](https://github.com/BMingSY/isaac-lan/blob/main/docs/party-compatibility.md)。

## 验收范围

先完成构建、脚本、离线状态与 Windows 传输检查，再集中覆盖：远端里店长的第一层商店、64／65／128 个跟班、口袋副手、药丸鉴定、分房公共道具、表／里店长和普通角色的恶魔交易、分房十字圣球／里 Lost 道具与神圣卡生成、死亡证明整队进入／分开探索／卡牌限制／整队返回、主机选择跑圈及主机拒绝跑圈。公共道具／角色与同步场景共用一个隔离主客机进程组；跑圈的两种顺序使用独立目录和 30220／30230 端口组并发检查，组内仍复用进程并清理会话与夹具。两端日志和画面分别归档，避免互相覆盖。具体隔离与输入约束见[并发验收安排](https://github.com/BMingSY/isaac-lan/blob/main/docs/development-and-testing.md#最终实机验收)。

## 合成袋追加验证

用户反馈的双里该隐画面暴露了此前 #41 验收的遗漏：口袋主动的 ID／顺序一致，不代表该道具的私有材料已同步。新增离线用例执行生产世界采集／编码／应用链路，覆盖两名玩家不同的完整／部分材料、重复视图、同 tick 多视口缓存、分房、材料重排、合成清空、丢失道具、合作幽灵、新局和楼层屏障。追加后 67 项 CTest 通过；分层与 Linux 安装器 11 项 Python 检查、脚本／格式检查、Windows x86 构建及实际 J460 的 159 个入口／布局位置校验通过。

Windows 集中实机的 2026-10-13 合成袋原生第 9 轮 使用一对进程完成非空部分材料的原生拾取、双方全部角色的状态与 HUD、分房、移除／恢复合成袋及换层保留检查。主客机每份已应用视图的 12 字节原生记录均与对应权威角色一致；两端原版 HUD 分别显示各自材料及远端玩家材料，移到上方中间的延迟文字不再覆盖材料格。进程均正常退出，堆观察器通过且没有崩溃转储。DLL SHA-256 为 `5c1aeaba3c839ee92f81c0d99230d3f35b0208731fe52b7181cdcac8b1c05b3e`；移动延迟文字前的 r8 同一场景也通过。

自动夹具未完成装满预览、第九个材料挤出旧材料、真实重排和真实合成清空的原生验证，这些仍需手动核对；离线覆盖不作为这些实机场景通过的证据。r1 的大厅选择／开局设置不一致、r2–r4 的拾取未触发、r5／r7 只收集到第一份材料、r6 的夹具枚举名错误均保留为失败。后续将夹具范围明确限定为部分材料，并使用原版实体碰撞执行拾取，没有改动生产玩法。失败已使会话终止，无法继续原场景时重启实验室；未响应正常关闭的进程由工具仅对其持有的 PID 强制结束，退出失败与观察器结果亦保留，没有计为通过。上述证据记录于验收归档（2026-10-13）。
