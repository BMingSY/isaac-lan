# 过门前冲补充验证：2026-10-24

候选 `9b7b8af` 修复客机持续按方向过门时的前冲。基线为 `c479e34`，即 [10 月 23 日反馈专项](https://github.com/BMingSY/isaac-lan/blob/main/docs/history/feedback-validation-20261023.md) 的生产 DLL；此前专项核对到达和渲染间隔，没有断言淡入期间的位移，因此不能覆盖这次用户实测指出的问题。本记录保留旧版失败结果，不替代原专项或发布验收。

## 原因与修复范围

旧版把同层旧房间的移动持有值继续用于目的地；切房又发生在完整更新之后，紧随的半帧会先推进一次旧输入。客机淡入与移动预测、发送输入没有使用同一个控制窗口，导致到达时已经存在权威位移，并继续重放本机方向。

主机完整更新及切房后的半帧均检查输入所属房间；旧房间输入保留同层射击持有值，停止移动和物品边沿。客机目的地淡入期间同时停止移动预测及发送移动值，结束后直接响应当前方向；取消过门不进入到达锁定。没有增加原生布局、Hook 或网络字段。世界 schema 31、协议 39 保持不变，双端使用相同构建。

## 双实例对照

Windows x86 `1.9.7.17.J460`，每方向 40 ms 延迟，无额外抖动或丢包；实测 RTT 基线 81–84 ms、修复版 81–85 ms，中位数均为 84 ms。同一组进程完成客机进入新房、返回驻留房间及主机独自进入另一房间。固定种子和普通以撒输入相同，正常方向输入触发走门；基线与修复版分别启动以加载不同 DLL。夹具整理只删除无用变量和恒真条件并格式化，场景时序与断言相同。
