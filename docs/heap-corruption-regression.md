# J460 测试夹具堆损坏回归

## 范围与根因

Issue #25 记录了隔离路线验收中的加载／退出异常 `0xC0000374`。堆检查报告的是损坏被发现的位置；早期转储分别落在原生大厅精灵与资源字符串释放处，不能据此判断是这些析构函数导致损坏。

在同一测试链路中，临时分配保护捕获到角色菜单的越界写入：J460 游戏模块相对地址 `0x54bfac`，访问异常 `0xC0000005`，写入索引 14。菜单构建时缓存 14 个可选角色，分配了 14 × 16 字节的记录空间。旧 `lab_progress.ps1` 随后用 `WriteProcessMemory` 解锁全部成就，原版绘制根据新解锁表写入更多角色记录，而容量仍是旧值。

现场向量的起点为 `0x3bab0f1c`，终点与容量终点均为 `0x3bab0ffc`；原生分配为 228 字节（4 字节分配头与 224 字节记录）。故障写地址 `0x3bab1000` 落在该分配后方的保护页。记录显示分配仍存活，未发生提前释放。分配调用链包含游戏相对地址 `0x66493a → 0x60f4d4 → 0xcf3a → 0x54bf45`。这解释了损坏相邻对象后在加载或退出时才被发现的现象。

此证据限定为该隔离夹具触发链路，不把所有玩家遇到的同码异常都归为同一个原因。

## 修复与边界

- 将夹具解锁移至游戏启动前的隔离存档准备，原版读取存档后按一致的解锁状态建立菜单。
- 启动后的 PowerShell 夹具只读核对成就和计数器，不再写游戏进程内存。
- 增加原版校验算法、文件区段、主客机进度差异与隔离目录范围的离线回归。
- 保留原版分配、释放和异常处理链；没有跳过析构、屏蔽异常或修改生产游戏后端。

定位使用的分配保护只存在于本地诊断构建，正式提交和安装包不包含该保护。提交中的外部异常观察器只用于已标记的实验目录，并在异常处理后继续原版链路。

## 验收记录

- Linux：48 项 CTest、75 项 Python 测试及 19 项子测试通过；ASan／LSan／UBSan 构建的 48 项 CTest 通过，无 sanitizer 报告。
- Windows x86 Release：72 项 CTest 通过，包括 40 轮网络会话、40 局日志／指标资源回归；本地安装包及系统 DLL 依赖校验通过。
- 合成异常观察器：超过 2 GiB 虚拟地址空间的独立夹具触发 `C0000374`，完整转储和非零退出检测通过，产物 `artifacts/heap-observer-final-20261011/`。
- 内存保护回归 r16：同一对主客机先验证共有诅咒，再从第一层经 1–8、10、11 层到羔羊结局。双方原版胜利回调、进度恢复、隔离存档恢复通过；PID 39264／37360 均以 `00000000` 退出，外部观察器无异常转储。产物 `artifacts/diagnostics-guard-r16-20261011/`。该构建仅用于越界检查，不作为性能基线。

- 正式构建 r18：复用一对主客机完成相同共有诅咒与整局通关，单向延迟 75 ms、默认不录制画面，总计 391.4 秒。双方胜利回调、本地进度恢复、隔离存档恢复通过；PID 37052／32936 退出码均为 `00000000`，两个外部观察器均正常结束、转储数量 0。DLL SHA-256：`15c2609cc74c014023ef48696c9e949c601af9e12a20822d913c2e21994f1b05`。产物 `artifacts/diagnostics-final-r18-20261011/`。
- r18 的通关局两端各有 325 个性能窗口；主机采集加权平均 4.319 ms，客机应用 2.470 ms。客机应用最大 89.287 ms，最慢窗口 p95 为 14.472 ms，说明报告会保留尖峰。主客机句柄首尾分别为 963→947、940→939。跨楼层私有内存变化包含原版资源加载，不据此认定泄漏或宣称客机卡顿已经解决。

正式构建首轮 r17 因 TCP 端口不可用，未建局、未启动客机，不计为通过；主机 PID 33752 正常退出且隔离存档恢复。更换独立端口后执行 r18。r16→r17 重启用于移除定位保护、加载正式 DLL，并验收启动／退出；r17→r18 重启用于恢复被建房失败中断的夹具。未关闭或改动其他实验目录和正式 Steam 游戏。

首次 GitHub Windows CI 的网络、配置、日志资源检查均通过；合成观察器因 `RUNNER~1` 短路径与规范路径的字符串比较失败而拒绝自己的夹具。观察器改为核对句柄解析后的最终路径，并继续要求游戏及其目录位于实验目录内。本地长路径和 `ADMINI~1`／`ISAAC-~2` 短路径合成检查均通过；Windows CI 的合成启动器显式使用可用的短路径，防止该问题随环境变化被遗漏。此修复只影响观察器工具，不改变已验收的生产 DLL。
