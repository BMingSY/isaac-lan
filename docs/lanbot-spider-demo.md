# LANBOT 九蜘蛛纯走位演示

本场景观察关闭射击后的现有 LANBOT 走位。生产 LANBOT 的目标选择、站位和避险策略保持原样；只在测试夹具的 `native.input_bot` 包装器中保留四个移动位，屏蔽射击。它不是新增的纯避险模式，也没有为这次演示调整生产策略。

## 场景与判定

- 种子 `YV039KQF`，普通难度，客机以撒，初始三颗红心、移速 1；主机放在另一个房间，避免成为同房目标。
- 初始房间中心生成 3×3 共九只普通 Spider，间距 40。房门关闭，客机初始位置在中心左侧 180。
- 测试回调先暂停这九只蜘蛛的内部 AI，检查其位置不变。客机观察到场景三秒后启动 `hold + balanced` 的 LANBOT；主机收到真实客机移动输入后解除暂停并开始计时。
- 释放后不再写角色位置、速度、生命值或蜘蛛状态。蜘蛛使用原版 AI、伤害、碰撞及受击无敌帧。
- 以主机权威生命值每次下降半颗心计算受击次数；伤害回调另记为尝试，不作为实际受击数。每次下降必须恰好一个半心单位；死亡必须伴随六次下降。
- 全程要求九只蜘蛛存活且未掉血、没有原生泪弹、客机未离开初始房间，并确实观察到角色和蜘蛛移动。
- 死亡结束；若达到 180 秒未死亡，则报告存活时间的下限。同时记录墙钟秒数及 30 Hz 权威模拟秒数，避免慢速模拟造成误判。

暂时冻结 AI 使用 [MC_PRE_NPC_UPDATE 的返回值](https://wofsauge.github.io/IsaacDocs/rep/enums/ModCallbacks.html#mc_pre_npc_update)，释放后回调不再阻止 AI。关闭射击及回调都是夹具范围内的设置，结束时清理并恢复原输入接口。

## 重现

先完成离线检查：

```sh
lua5.3 tests/lanbot_spiders_fixture.lua "$PWD"
python tools/check_scripts.py
ctest --test-dir build-offline -R 'bridge.lanbot' --output-on-failure
```

生命周期模型执行实际夹具，检查先冻结后释放、真实客机移动输入作为释放条件、重复伤害尝试不增加受击数、六次血量下降、射击输入过滤及释放后的角色写入禁令。它不代替原版物理和真实走位验收。

最终实机使用两份有 `.isaac-lan-lab` 标记且空闲的隔离目录，主客机各启动一次；保护包装器结束后恢复原存档、配置与会话文件。工具默认不录画面。下面显式开启客机录制；仅做状态验收时可省略最后两个录制参数：

```sh
python tools/run_special_routes.py \
  --host /mnt/d/isaac-lan-lab/host-001 \
  --client /mnt/d/isaac-lan-lab/client-001 \
  --build build-win32 \
  --output artifacts/lanbot-spiders-new-run \
  --case lanbot-spiders --port 30990 --latency-ms 75 --heap-check \
  --record-client --frame-ms 50
```

双方日志中的 `LANBOT_SPIDERS` 保存夹具就绪、释放、实际受击、存活时间和输入证据。结果摘要为 `report.json`，进程／DLL／夹具指纹、异常转储与原生退出结果为 `engine/result.json`。录制只读取客机帧缓冲，不依赖截图判定通过。

## 2026-10-11 实测

当前主线生产 DLL（基于 `30633fa`）在 `artifacts/lanbot-spiders-r2-20261011/` 完成一轮实测。主机 PID 12808、客机 PID 5800，各启动一次、各开局一次；同机双开并加入单向 75 ms 延迟。客机默认 `balanced` 风格，记录到 1,018 次移动输入采样；原生角色实际移动 464 个权威观察间隔。

**从蜘蛛释放至死亡为 15.531 秒**，对应 15.533 秒权威模拟时间。实际受击时间如下，每次损失半颗红心：

| 次数 | 释放后墙钟秒数 | 剩余红心 |
| --- | --- | --- |
| 1 | 2.687 | 2.5 |
| 2 | 3.890 | 2 |
| 3 | 7.421 | 1.5 |
| 4 | 9.000 | 1 |
| 5 | 13.765 | 0.5 |
| 6 | 15.531 | 0 |

九只蜘蛛全部存活且血量未变，主客机泪弹数均为零；两端完成标记、原生退出码 0、堆异常监视退出码 0、转储数 0，隔离存档散列恢复通过。客机采集 531 帧，丢帧数 0；`lanbot-spider-dodge.mp4` 保留布置、启动、移动及死亡过程，`survival.json` 保存受击时间，`staged.png` 和 `death.png` 保存原生帧。首段有 EID 的开局警告覆盖部分画面；没有因显示提示额外重启游戏。

受测 DLL SHA-256：`934dace7c51e5abdbb51204d217934fa4d9cb7f354254b6ced607fc9530b4a23`；组合夹具 SHA-256：`39d94d4c13f892c68d97dff8a5926b6f8f50041cb1e5d733b04df01c3fcd2926`。离线新增夹具及原有 LANBOT 两项 CTest 通过，工具测试 29 项及 19 项子测试通过，Python／Lua／组合夹具语法检查通过；生产代码和 DLL 未修改。

此前 `r1` 只启动主机，因新夹具没有输出启动工具要求的完整 `LAN_NETWORK MENU_READY` 标记而终止，未进入蜘蛛场景；正常退出、存档恢复通过。这属于夹具入口错误，不能作为走位结果。修正标记并加入离线断言后，重新启动隔离进程加载新夹具，完成上述 `r2`。两轮日志均保留。

同条件下存活时间更长、首次受击更晚，可以作为走位改进的指标。当前只有一个种子的一次试验；比较策略时需要固定难度、角色、初始位置、蜘蛛阵形、延迟与录制条件，多次运行比较首次受击和存活时间，不能用这一次数值代表整体走位水平。
